# 창

채팅창, 설정창, 시작하기 창이 어떻게 보이는지 정한다.

## 배경

주인은 하루에도 여러 번 채팅창을 연다. 비서다운 느낌이 들도록 창의 모양을 한 가지 규칙으로 맞춘다.

## 내용

- 색은 DESIGN.md의 테마 가운데 주인이 고른 것을 쓴다.
- 기본은 도토리다.
- 모든 창이 같은 테마를 쓴다.
- 설정창 맨 위의 "이름과 아이콘" 카드에서 비서의 이름과 그림을 정한다.
- 이름을 비워 두면 Dotori다.
- 창 문구에서 비서를 가리키는 곳은 정한 이름을 쓰고, 조사는 이름의 끝소리에 맞춘다.
- 프로그램을 가리키는 곳(다시 시작, 창 제목, 트레이, 다른 PC)도 정한 이름을 쓴다.
- 창 문구에는 소문자 dotori를 쓰지 않는다.
- 그림은 주인이 올린 그림을 사진의 방향대로 세워 가운데 정사각형으로 잘라 작은 PNG로 `icons` 폴더에 두고, 모서리가 둥근 사각형 타일에 채워 그린다.
- `icons` 폴더에는 쓰는 그림과 최근 그림 몇 개만 남긴다.
- 그림을 정하지 않으면 도토리 로고를 그리고, 그림을 누르면 뜨는 메뉴의 "기본 그림으로 되돌리기"로 언제든 돌아간다.
- 설정창과 시작하기 창은 같은 그림 타일을 쓰고, 연필 배지가 달린 타일을 누르면 그림을 고른다.
- 이름과 그림 설명에는 그 일과 상관없는 다른 PC 이야기를 넣지 않는다.
- 그림과 로고는 창에 그려지는 크기의 두 배로 만들어 창에 넘긴다.
- 그림은 고르면 바로 저장되고, 이름은 칸을 벗어나면 저장된다.
- 열린 창은 설정 파일이 바뀌면 이름과 그림, 창 제목을 바로 바꾼다.
- 데몬도 설정 파일이 바뀌면 이름과 언어를 바로 다시 읽는다.
- 트레이와 채팅방에 보내는 카드와 안내는 첫 실행에서 정한 이름이나 설정에서 바꾼 이름을 다시 시작하지 않아도 쓴다.
- 모델에게 주는 지시문에도 정한 이름을 넣고, 이것도 바로 적용된다.
- 설정창의 테마 카드에서 테마와 밝게, 어둡게, 시스템 따라를 고르면 바로 저장되고, 열린 창이 모두 바로 바뀐다.
- 테마의 색은 DESIGN.md에만 적고, 창의 코드는 거기서 만든다.
- 창의 표시는 도토리 로고이고, 밝은 모양과 어두운 모양에서 로고의 색을 따로 쓴다.
- 모양을 "시스템 따라"로 두면 시스템이 어두울 때 어두운 색으로 그리고, 시스템이 바뀌면 바로 따라간다.
- 설정 파일을 읽지 못하면 창은 지금 모양을 지킨다.
- 손으로 고치는 중인 파일이 있어도 테마가 바뀌지 않는다.
- 모양을 고르면 창은 바로 바뀌고, 저장은 그리는 스레드 밖에서 고른 순서대로 한다.
- 다른 창은 설정 파일이 바뀐 것을 보고 따라간다.
- 주 버튼은 글자색을 채우고 바탕색으로 글자를 쓴다.
- 주 버튼은 한 화면에 하나만 둔다.
- `primary`는 끝난 단계의 체크, 고른 것의 체크, 목록 표시, 고른 칸의 테두리 같은 작은 표시에만 쓰고, 글자나 버튼 바탕으로는 쓰지 않는다.
- 체크 칸은 체크되면 주 버튼의 색으로 채우고 바탕색으로 체크를 그린다.
- 채팅창에는 머리도 OS 제목 표시줄도 없다.
- 위쪽 얇은 줄 왼쪽에 설정 버튼, 오른쪽에 닫기 버튼을 둔다.
- 대화와 옆 패널은 위쪽 줄 아래로 지나가게 스크롤하고, 위쪽 줄은 자기 바탕 없이 버튼만 그 위에 띄운다.
- 위쪽 줄 자리에는 바탕색에서 투명으로 옅어지는 덮개를 두어, 지나가는 글이 버튼 근처에서 사라지게 한다.
- 설정 버튼은 같은 창 안에서 설정을 보여 주고, 설정이 보이는 동안 숨는다.
- 설정 목록 맨 위의 "대화"를 누르면 대화로 돌아가고, 입력창에 쓰던 글과 포커스가 그대로 남는다.
- 설정은 열 때마다 설정 파일을 다시 읽어, 다른 PC에서 바뀐 값도 보여 준다.
- 설정이 보이는 동안 채팅에 주인이 답할 카드가 오면 "대화" 옆에 "답을 기다려요"를 적는다.
- 설정 칸에서 누른 Enter는 채팅으로 가지 않는다.
- 창이 어떻게 닫히든, dotori가 꺼져서 닫혀도 설정에 쓰던 값은 저장한다.
- 닫기 버튼은 창을 닫는다.
- 대화 왼쪽에는 루틴과 메모를 보여 주는 옆 판이 있고, 5초마다 다시 읽는다.
- 옆 판의 "루틴"과 "메모" 제목을 누르면 설정의 그 부분으로 간다.
- 트레이의 "설정"과 `dotori settings`는 대화 창을 설정이 보이는 채로 연다.
- 그 줄을 잡고 창을 옮긴다.
- 비서 그림은 어느 창에서나 같은 그림 타일로 보이고, 스플래시와 빈 대화, 설정도 그 타일을 쓴다.
- 채팅창의 답과 생각하는 표시에는 그림을 두지 않는다.
- 대화의 글은 끌어서 여러 메시지에 걸쳐 고를 수 있고, 입력창에 키보드를 둔 채 복사 키로 복사한다.
- 글을 두 번 누르면 그 낱말을, 세 번 누르면 줄바꿈까지의 그 줄을 고른다.
- 복사한 글은 낱말 사이에 띄어쓰기, 문단 사이에 줄바꿈, 메시지 사이에 빈 줄을 넣는다.
- 트레이 아이콘과 작업 표시줄 아이콘은 주인이 정한 그림을 창 안의 타일과 같은 둥근 사각형으로 잘라 보이고, 그림이 없으면 도토리를 보이며, 그림이 바뀌면 바로 바뀐다.
- Windows 실행 파일에는 도토리 아이콘을 넣어 작업 표시줄과 파일에 보인다.
- Windows에서는 창을 열 때와 그림이 바뀔 때 작업 표시줄의 창 아이콘도 주인이 정한 그림으로 바꾼다.
- 창 바탕은 모든 OS에서 불투명한 단색이다.
- 카드, 입력 칸, 입력창, 목록은 `surface`에 옅은 두 겹 그림자를 두고 테두리를 두르지 않는다.
- 어두운 모양에서는 카드 위쪽 가장자리에 `rim`을 둔다.
- 카드 안에서 고른 것은 작은 그림자로 살짝 떠 있다.
- 허락을 기다리는 카드처럼 뜻이 있는 색의 카드는 그 색을 지키고 같은 그림자를 가진다.
- 위쪽 줄에는 글을 적지 않는다.
- 위쪽 줄은 창 끝에서 6px 아래부터 끌기 영역이다.
- 그 6px은 위쪽 가장자리로 크기를 바꾸는 자리로 남긴다.
- 끌기 영역의 누름은 그 뒤로 지나가는 대화에 닿지 않는다.
- Windows에서는 끌기 영역의 누름을 앱이 받지 않고 OS에 넘겨, 창 옮기기와 두 번 눌러 최대화하기를 OS가 한다.
- 창 버튼은 최소화, 최대화, 닫기이고, 위쪽 줄을 두 번 누르면 최대화하거나 원래 크기로 돌린다.
- 최대화된 동안 최대화 버튼은 겹친 네모를 그리고, 가장자리로 크기를 바꾸지 않는다.
- Windows에서는 최소화, 최대화, 닫기를 OS의 캡션 버튼 영역으로 알린다.
- 창 버튼은 끌기 영역 밖에 둔다.
- 리눅스에서 직접 그릴 때도 두 버튼을 두고, 창이 화면 가장자리에 붙은 쪽으로는 크기를 바꾸지 않는다.
- macOS에서는 시스템의 창 버튼을 왼쪽에 그대로 두고 설정 버튼을 그 뒤에 둔다.
- 닫기는 시스템 버튼이 한다.
- 리눅스에서는 창 관리자가 직접 그리기를 받아 줄 때(컴포지터와 `_GTK_FRAME_EXTENTS`가 있는 GNOME, KDE 같은 환경)만 OS 제목 표시줄을 숨기고 닫기 버튼과 가장자리 크기 조절을 직접 한다.
- 그렇지 않으면 OS 제목 표시줄이 남고, 닫기는 그쪽에 맡긴다.
- 채팅창은 잘 될 때 상태를 적지 않는다.
- dotori가 켜지는 동안 채팅창은 대화와 입력창 대신 스플래시를 보여 준다.
- 떠 있는 dotori에 붙을 때 스플래시가 깜빡이지 않도록, 연결에서 아직 아무 소식도 받지 못한 처음 잠깐은 버튼 없는 위쪽 줄만 그린다.
- 스플래시는 버튼 없는 위쪽 줄과 가운데의 비서 그림뿐이고, 그림은 motion.working으로 숨 쉰다.
- 스플래시의 그림과 이름은 주인이 정한 것을 쓴다.
- 켜지 못했을 때만 위쪽 줄의 설정과 창 버튼이 다시 나와서 창을 닫을 수 있다.
- 스플래시에는 글을 적지 않는다.
- 창이 dotori를 켠 뒤 잠금이 한동안 잡히지 않으면 스플래시의 그림이 멈추고, 그 아래에 켜지 못했다는 것과 앱을 다시 열라는 말을 적는다.
- 잠금이 잡히면 이어서 연결한다.
- 연결된 뒤 dotori에 닿지 않을 때만 입력창 아래 Enter 안내 대신 무슨 일인지 적는다.
- 끊음, 닿지 않음, 그 밖의 실패를 나눠 적는다.
- 연결된 뒤 dotori가 다시 켜지는 중이면 스플래시로 돌아간다.
- 창이 한 번이라도 잠금이 잡힌 것을 봤다면 그 뒤 잠금이 풀려도 dotori를 다시 켜지 않는다.
- 채팅창을 열었을 때 dotori가 꺼져 있으면 창이 dotori를 한 번 켜고, 그동안 스플래시를 보여 준다.
- 잠금이 잡힌 것을 본 뒤 dotori가 꺼지면 채팅창도 닫힌다.
- 설정창과 시작하기 창도 잠금이 잡힌 것을 본 뒤 풀리면, 입력 중이던 칸을 저장하고 닫힌다.
- dotori가 떠 있는 채로 연결만 끊기면 창이 다시 연결한다.
- 데몬이 잠금을 잡았는데 연결 파일이 아직 없으면 켜는 중으로 보고 스플래시를 보여 준다.
- 어느 PC가 답하는지는 창에 적지 않는다.
- 채팅창은 첫 인사를 보통 답으로 보여 주고, 첫 인사를 시킨 안내는 보여 주지 않는다.
- 대화가 비어 있어도 dotori가 일하는 중이면 빈 화면 인사 대신 생각하는 표시만 보여 준다.
- 상태를 색 점으로 보여 주지 않는다.
- 주인의 말은 오른쪽의 `bubble` 말풍선이다.
- dotori의 답은 왼쪽 말풍선에 쓰고, 그 옆에 그림을 두지 않는다.
- dotori의 답은 목록, 번호 목록, 제목, 굵은 글씨, 코드 같은 가벼운 마크다운을 꾸며서 보여 준다.
- 짝이 맞지 않는 표시는 쓴 그대로 둔다.
- 창의 글은 실행 파일에 넣은 카카오 작은글씨(Kakao Small Sans)로 쓴다.
- 카카오 작은글씨의 OFL 라이선스는 `crates/app/fonts/OFL.txt`에 둔다.
- 카카오 작은글씨의 합자는 꺼서 `->`나 `:-D`를 쓴 그대로 보인다.
- 코드와 명령은 OS마다 정한 고정폭 글꼴로 보여 준다.
- 다른 채널의 대화는 채널, 방, 말한 사람을 작은 흐린 줄로 위에 적고, 말은 그 아래 `surface` 카드에 둔다.
- 주인에게만 보낸 답은 방 대신 "주인에게만"으로 적는다.
- 카드와 버튼에는 테두리를 두르지 않고 바탕색으로 나눈다.
- 선은 머리와 대화, 대화와 입력창처럼 큰 영역 사이에만 쓴다.
- 대화가 없으면 무엇을 할 수 있는지 짧게 안내한다.
- 글은 띄어쓰기에서만 줄을 바꾼다.
- 한글 단어가 중간에서 끊기지 않는다.
- 입력창은 그림자가 옅은 둥근 칸과 둥근 보내기 버튼이고, 그 아래에 Enter 안내를 적는다.
- 입력창은 여러 줄을 받는다.
- 입력창에 키보드가 있으면 다른 입력 칸처럼 `primary` 테두리를 두른다.
- Enter는 보내고 Shift+Enter는 줄을 바꾼다.
- 글을 받는 칸은 Ctrl+Z로 되돌리고 Ctrl+Y나 Ctrl+Shift+Z로 다시 한다.
- 이어 친 글은 낱말 단위로, 이어 지운 글은 한 번에 되돌린다.
- 보낸 글은 되돌려 오지 않는다.
- 글이 길어지면 8줄까지 커지고, 그 뒤로는 칸 안에서 스크롤하며 커서를 따라간다.
- 말에는 시간을 늘 적지 않는다.
- 마우스를 올리면 그 말 아래에 복사 아이콘과 시간이 나오고, 복사하면 아이콘이 잠깐 체크로 바뀐다.
- 그 줄은 비어 있을 때도 자리를 지켜서 마우스가 오가도 아무것도 밀리지 않는다.
- 시간은 그 말을 처음 보여 준 PC가 재고, 창은 이 PC의 시간대로 "오후 3:07"처럼 읽는다.
- 날이 바뀌면 "오늘", "어제", "11월 2일 월요일" 같은 줄을 넣는다.
- dotori가 허락을 기다리는 도구 호출은 `warn-soft` 바탕 카드로 보여 준다.
- 서버와 도구 이름, 넘길 내용을 항목별로 적고 "거절"과 "허락" 버튼을 둔다.
- 정해지면 카드는 `surface`로 돌아온다.
- 허락하면 버튼 자리에 생각하는 표시가 나오고, 끝나면 그 카드 안에 결과를 "결과" 아래에 보여 준다.
- 실패하면 카드에는 `danger`로 느낌표 아이콘과 "오류"만 적고, 도구가 남긴 오류 문구와 명령의 출력은 보이지 않는다.
- 성공했는지 실패했는지 적는 줄은 두지 않고, dotori의 답이 말한다.
- 거절하면 버튼 대신 "거절했어요"를 적는다.
- 셸 명령이 샌드박스 안에서 돌 때만 명령 아래에 방패 표시와 함께 그렇다고 한 줄 적는다.
- 복사 아이콘을 누르면 그 말 전체를 복사한다.
- 주인이 한 일은 바로 보인다.

- 채팅창, 시작하기 창, 설정창은 모두 같은 `size.window`로 열린다.
- 채팅창의 대화와 입력창은 가운데 `size.column` 폭 안에 두고, 시작하기 창의 각 화면은 가운데 `size.walk` 폭에 둔다.
- 모든 창은 `size.window-min`까지 줄일 수 있다.
- 창과 그림의 크기, 그림 타일과 할 수 있는 일 타일의 색은 `tokens.rs`에 두고, 테스트가 DESIGN.md와 같은지 확인한다.
- 시작하기 창도 다른 창처럼 크기를 바꾸고 최대화할 수 있다.
- 첫 화면은 왼쪽에 인사와 시작하기 버튼, 오른쪽에 할 수 있는 일을 짧은 대화로 보여 주는 카드를 둔다.
- 화면은 인사, API 키, 이름과 테마, 연결 네 개이고, 한 화면에 하나만 보인다.
- 인사는 가운데에 선 도토리 타일, "안녕하세요, {이름}예요", 무엇을 하는지 두 줄, 할 수 있는 일 세 줄이다.
- 할 수 있는 일은 줄마다 색 타일 아이콘, 굵은 제목, 따옴표에 넣은 부탁 예시다.
- 인사를 열면 그림이 `motion.greet`로 내려와 앉고, 나머지가 차례로 `motion.message-enter`로 올라온다.
- 인사의 버튼은 "시작하기"다.
- 인사의 버튼 아래에는 조용한 글자 버튼 "기존 PC에 연결하기"가 있고, 누르면 기존 PC 화면이 열린다.
- 기존 PC 화면은 인사에서만 열리고, 단계 목록이 없다.
- 기존 PC 화면은 연결 코드와 주소 칸을 두고, 주소는 코드에 없을 때만 적는다.
- 연결은 설정창의 여러 PC 카드와 같은 방법으로 한다.
- 설정창의 여러 PC 카드는 이 PC의 이름 칸을 두고, 비어 있으면 칸에 컴퓨터 이름을 흐리게 보여 준다.
- PC 이름은 칸을 벗어나면 저장한다.
- 연결하는 동안 칸은 멈추고 "이전"은 숨는다.
- 실패하면 칸 아래에 이유를 적고 칸을 다시 연다.
- 기존 PC가 아니라 이 PC에서 실패했으면(연결 장부를 저장하지 못했을 때 등) 그렇다고 따로 말한다.
- 코드를 읽지 못하면 코드 칸을, 주소를 알 수 없으면 주소 칸을 `danger`로 두르고 그 칸 아래에 적는다.
- 기존 PC에 닿지 못했거나 코드를 거절당했으면 주소 칸 아래에 적는다.
- 연결되면 모델과 키가 이 PC에 들어왔는지 계속 보고, 들어오면 버튼이 "대화 시작"이 된다.
- 들어오기 전에는 버튼이 "설정과 키를 받고 있어요"로 멈추고, 그 아래 "여기서 직접 설정하기"가 API 키 화면으로 넘어간다.
- "여기서 직접 설정하기"는 디스크에 있는 설정으로 칸을 다시 채운 뒤 넘어간다.
- 기존 PC 화면의 "대화 시작"은 채팅창을 열고 시작하기 창을 닫는다.
- 첫 실행을 끝내지 못하면 화면은 그대로 두고 푸터에 이유를 적는다.
- 나머지 세 화면은 설정처럼 왼쪽에 단계 목록을 두고, 끝난 단계에는 체크를, 지금 단계에는 번호를 주 버튼 색으로 보인다.
- 단계를 넘기면 화면 전체가 `motion.step`으로 흐려졌다가 나타나며, "다음"이면 오른쪽에서, "이전"이면 왼쪽에서 `spacing.slide`만큼 미끄러져 들어온다.
- API 키 화면은 Anthropic이면 키 칸만, OpenAI 호환이면 주소, 모델, 키 칸을 보인다.
- OpenAI 호환의 모델은 설정창과 같이 서버가 알려 주는 목록에서 고른다.
- Anthropic을 고르면 설명 옆에 키를 만드는 페이지로 가는 "키 만들기"를 둔다.
- API 키 화면에 들어가면 키 칸에 커서를 둔다.
- API 키 화면은 키가 환경 변수나 vault에 있어야 넘어가고, 없으면 칸을 `danger`로 두르고 칸 아래에 이유를 적는다.
- 키가 필요 없는 OpenAI 호환 모델은 그냥 넘어간다.
- 시작하기 창에서는 vault를 "금고"라고 부르지 않고 "PC에 암호화되어 보관돼요"처럼 하는 일로 적는다.
- 이름과 테마 화면은 비서의 그림 타일 오른쪽 아래에 연필 배지를 늘 달고, 타일을 누르면 그림을 고른다.
- 테마는 설정창의 테마 카드와 같은 목록과 밝기 고르기를 쓴다.
- 연결 화면은 Slack, Telegram, Discord를 스위치로 켜고, 켠 것만 토큰과 내 ID 칸을 연다.
- 켠 채널은 토큰이 환경 변수나 금고에 있거나 칸에 적혀 있어야 넘어간다.
- 토큰은 켠 채널의 것만, 연결 화면에서만 금고에 넣는다.
- 연결 화면의 버튼은 "대화 시작"이고, 채팅창을 열고 시작하기 창을 닫는다.
- API 키 화면부터 "다음"은 설정창의 저장과 같은 저장을 하고, 실패하면 아래 줄에 적고 그 화면에 남는다.

## 미정

- 입력창을 대화 위에 띄워 지나가는 글을 흐리게 비추는 것은 창 안 요소별 블러가 있어야 한다. GPUI 0.2.2에는 없어서 렌더러 패치가 필요하다.
- GPUI 0.2.2는 시스템의 움직임 줄이기 설정을 읽지 못한다. 읽을 수 있게 되면 그때 움직임을 제자리 바꿈으로 바꾼다.
- 버튼 색이 마우스에 따라 `motion.hover`로 바뀌는 것과 테마를 바꿀 때의 cross-fade는 아직 없다. 지금은 바로 바뀐다.
- 도구 호출을 한 줄로 접었다 펴는 모양은 창이 도구 호출을 받게 되면 만든다.
