# 프로세스 구조

dotori를 어떤 프로세스로 나눠 실행하는지 정한다.

## 배경

비서는 창을 닫아도 계속 돌아야 한다. GPUI는 창을 닫아도 메모리를 다 돌려주지 않는다.

## 내용

- 데몬과 화면을 별도 프로세스로 나눈다.
- 데몬은 에이전트와 트레이를 맡고 항상 돈다.
- `dotori`는 트레이와 데몬을 함께 띄운다.
- 화면 없이 도는 방식은 두지 않는다.
- 화면이 없으면 `dotori`는 시작하지 않고 끝난다.
- 화면은 창을 열 때만 뜨는 GPUI 프로세스다.
- 앱 채널의 클라이언트로 데몬에 연결한다.
- 데몬과 화면은 127.0.0.1의 TCP로 한 줄에 JSON 하나씩 주고받는다.
- 데몬은 시작할 때 포트와 토큰을 사용자만 읽을 수 있는 파일에 쓰고, 화면은 첫 줄로 토큰을 보낸다.
- 토큰이 틀리면 끊는다.
- 앱 채널에 들어온 사람은 모두 주인이다.
- 모든 창이 같은 메인 세션을 본다.
- 창이 연결되면 최근 대화를 먼저 받고, 이후는 실시간으로 받는다.
- 데몬은 시작할 때 원본 기록에서 마지막 200줄의 대화를 다시 만들어 최근 대화 앞에 둔다.
- 주인의 말, dotori의 답, 다른 채널의 말과 답이 기록된 시간과 함께 돌아온다.
- 보내지 못한 답은 빼고, 이 줄들은 다른 PC로 보내지 않는다.
- 꺼져 있는 동안 다른 PC에서 오간 대화는 이때 보이지 않고, 다음에 다시 시작할 때 보인다.
- 설정, 원본 기록, 연결 파일은 한 폴더에 둔다.
- `DOTORI_HOME`으로 바꿀 수 있다.
- 디버그 빌드는 `dotori` 대신 `dotori-dev` 폴더를 쓴다.
- 원본 기록은 연도마다 SQLite 파일 하나이고, 한 번에 저장하는 묶음은 한 트랜잭션이다.
- Linux에서 데몬, MCP 서버, 채팅창, 설정창은 같은 계정의 다른 프로그램이 메모리와 환경 변수를 읽지 못하게 스스로를 닫는다.
- 데몬은 실행하는 동안 잠금 파일을 잡는다.
- 두 번째 데몬은 시작하지 않고, 창은 잠금이 잡혀 있을 때만 연결 파일을 믿는다.
- 따라가지 못한 창은 끊는다.
- 창이 다시 연결해서 최근 대화를 받는다.
- API 키는 설정 파일에 쓰지 않는다.
- 설정에는 키의 이름만 적고, 값은 같은 이름의 환경 변수나 vault에서 읽는다.
- 채팅창(`dotori window`), 설정창(`dotori settings`), 시작하기 창(`dotori onboarding`)은 각각 별도 프로세스로 뜬다.
- 검색 평가(`dotori search-eval`)는 데몬 없이 원본 기록과 검색 색인을 직접 읽는다.
- `dotori sandbox install`은 데몬 없이 root로 돌며 Linux에 샌드박스 환경을 설치한다.
- 창은 연결이 끊기면 스스로 다시 연결하고, 다시 연결되면 받은 최근 대화로 화면을 새로 그린다.
- 설정창은 설정 파일만 고친다.
- 바뀐 설정은 데몬을 다시 시작하면 적용된다.
- 데몬은 첫 실행을 마칠 때까지 끝나지 않고 기다린다.
- 첫 실행을 어디까지 했는지는 dotori 폴더의 `first-run` 파일에 둔다.
- 그 파일이 없는데 모델 키가 있으면 첫 실행 전부터 쓰던 설치로 보고 바로 시작한다.
- 기다리는 동안 트레이를 띄우고 시작하기 창을 연다.
- 기다리는 동안에도 다른 PC와 연결하고, 다른 PC가 보낸 함께 쓰는 설정과 키를 받는다.
- 임대와 메인 세션은 모델이 준비된 뒤에 시작한다.
- 기다리는 동안 받은 다른 메시지는 모델이 준비되면 받은 순서대로 처리한다.
- 모델 키만 들어와서는 시작하지 않는다.
- 첫 실행을 마치면 다시 시작하지 않아도 그때의 설정으로 시작한다.
- 키가 없어지면 첫 실행을 마친 뒤에도 키가 들어올 때까지 기다린다.
- 트레이는 데몬 프로세스의 메인 스레드에서 GPUI 이벤트 루프 위에 띄운다.
- 에이전트는 다른 스레드에서 돈다.
- 트레이 메뉴는 채팅창 열기, 설정창 열기, 끝내기다.
- 창은 별도 프로세스로 띄운다.
- Linux에서는 GTK 없이 D-Bus로 트레이를 띄운다.
- 트레이를 못 띄워도 데몬은 계속 돈다.
- 창은 데몬이 토큰을 받아들인 뒤에야 연결된 것으로 본다.
- 끊긴 동안에는 입력을 보내지 않는다.
