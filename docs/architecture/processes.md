# 프로세스 구조

dotori를 어떤 프로세스로 나눠 실행하는지 정한다.

## 배경

비서는 창을 닫아도 계속 돌아야 하고, 사양 낮은 서버에서는 화면 없이 돌아야 한다. GPUI는 창을 닫아도 메모리를 다 돌려주지 않는다.

## 내용

- 데몬과 화면을 별도 프로세스로 나눈다.
- 데몬은 에이전트와 트레이를 맡고 항상 돈다. 서버에서는 데몬만 실행한다.
- 화면은 창을 열 때만 뜨는 GPUI 프로세스다. 앱 채널의 클라이언트로 데몬에 연결한다.
- 데몬과 화면은 127.0.0.1의 TCP로 한 줄에 JSON 하나씩 주고받는다.
- 데몬은 시작할 때 포트와 토큰을 사용자만 읽을 수 있는 파일에 쓰고, 화면은 첫 줄로 토큰을 보낸다. 토큰이 틀리면 끊는다.
- 앱 채널에 들어온 사람은 모두 주인이다. 모든 창이 같은 대화 하나를 본다.
- 창이 연결되면 최근 대화를 먼저 받고, 이후는 실시간으로 받는다.
- 설정, 원본 기록, 연결 파일은 한 폴더에 둔다. `DOTORI_HOME`으로 바꿀 수 있다.
- 원본 기록은 한 줄에 기록 하나인 JSON Lines 파일이다. 충돌로 잘린 마지막 줄은 버린다.
- API 키는 설정 파일에 쓰지 않는다. 설정에는 키가 든 환경 변수 이름만 적는다.
- 터미널에서 쓰는 `dotori chat`도 창과 같은 방식으로 연결한다.

## 미정

- 데몬을 다시 켠 뒤 창에 이전 대화를 보여주는 방식
- 데몬을 두 번 실행하는 것을 막는 방식
