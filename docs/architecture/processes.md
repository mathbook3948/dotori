# 프로세스 구조

dotori를 어떤 프로세스로 나눠 실행하는지 정한다.

## 배경

비서는 창을 닫아도 계속 돌아야 한다. GPUI는 창을 닫아도 메모리를 다 돌려주지 않는다.

## 내용

- 데몬과 화면을 별도 프로세스로 나눈다.
- 데몬은 에이전트와 트레이를 맡고 항상 돈다.
- 인자 없이 실행한 `dotori`는 화면이 있으면 트레이와 함께 데몬을 띄운다. `dotori daemon`은 트레이 없이 데몬만 띄운다.
- 화면은 창을 열 때만 뜨는 GPUI 프로세스다. 앱 채널의 클라이언트로 데몬에 연결한다.
- 데몬과 화면은 127.0.0.1의 TCP로 한 줄에 JSON 하나씩 주고받는다.
- 데몬은 시작할 때 포트와 토큰을 사용자만 읽을 수 있는 파일에 쓰고, 화면은 첫 줄로 토큰을 보낸다. 토큰이 틀리면 끊는다.
- 앱 채널에 들어온 사람은 모두 주인이다. 모든 창이 같은 메인 세션을 본다.
- 창이 연결되면 최근 대화를 먼저 받고, 이후는 실시간으로 받는다.
- 데몬은 시작할 때 원본 기록에서 마지막 200줄의 대화를 다시 만들어 최근 대화 앞에 둔다. 주인의 말, dotori의 답, 다른 채널의 말과 답이 기록된 시간과 함께 돌아온다. 보내지 못한 답은 빼고, 이 줄들은 다른 PC로 보내지 않는다. 꺼져 있는 동안 다른 PC에서 오간 대화는 시작한 뒤에 복제되므로 이때 보이지 않고, 다음에 다시 시작할 때 보인다.
- 설정, 원본 기록, 연결 파일은 한 폴더에 둔다. `DOTORI_HOME`으로 바꿀 수 있다.
- 원본 기록은 연도마다 SQLite 파일 하나이고, 한 번에 저장하는 묶음은 한 트랜잭션이다.
- 데몬은 실행하는 동안 잠금 파일을 잡는다. 두 번째 데몬은 시작하지 않고, 창은 잠금이 잡혀 있을 때만 연결 파일을 믿는다.
- 따라가지 못한 창은 끊는다. 창이 다시 연결해서 최근 대화를 받는다.
- API 키는 설정 파일에 쓰지 않는다. 설정에는 키의 이름만 적고, 값은 같은 이름의 환경 변수나 vault에서 읽는다.
- 터미널에서 쓰는 `dotori chat`도 창과 같은 방식으로 연결한다.
- 채팅창(`dotori window`)과 설정창(`dotori settings`)은 각각 별도 프로세스로 뜬다.
- 검색 평가(`dotori search-eval`)는 데몬 없이 원본 기록과 검색 색인을 직접 읽는다.
- 창은 연결이 끊기면 스스로 다시 연결하고, 다시 연결되면 받은 최근 대화로 화면을 새로 그린다.
- 설정창은 설정 파일만 고친다. 바뀐 설정은 데몬을 다시 시작하면 적용된다.
- 트레이는 데몬 프로세스의 메인 스레드에서 GPUI 이벤트 루프 위에 띄운다. 에이전트는 다른 스레드에서 돈다.
- 트레이 메뉴는 채팅창 열기, 설정창 열기, 끝내기다. 창은 별도 프로세스로 띄운다.
- Linux에서는 GTK 없이 D-Bus로 트레이를 띄운다. 트레이를 못 띄워도 데몬은 계속 돈다.
- 창은 데몬이 토큰을 받아들인 뒤에야 연결된 것으로 본다. 끊긴 동안에는 입력을 보내지 않는다.
