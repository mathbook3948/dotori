# Slack 연결

Slack을 채널과 연동으로 어떻게 쓰는지 정한다.

## 배경

dotori는 개인 PC에서 돌아서 Slack이 부를 공개 주소가 없다. Slack은 주인이 비서와 말하는 곳이 될 수도 있고, 비서가 읽고 대신 행동할 주인의 업무 공간이 될 수도 있다.

## 내용

- 채널과 연동은 따로 설정한다.
- 채널은 Socket Mode로 연결한다. 앱 토큰으로 연결을 열고, 봇 토큰으로 말한다.
- 두 토큰은 설정 파일에 쓰지 않는다. 설정에는 토큰이 든 환경 변수 이름만 적는다.
- 설정 파일에 `[slack]` 항목이 있을 때만 채널을 연결한다. 토큰이 없으면 Slack만 끄고 데몬은 돈다.
- 주인은 설정에 적은 Slack 사용자 하나다. 다른 사람은 모두 주인이 아니다.
- 비서에게 온 주인의 DM과, Slack 채널에서 비서를 멘션한 주인의 메시지만 받는다. 다른 사람과 봇의 메시지, 수정과 삭제 같은 이벤트는 받지 않는다.
- 참가자는 Slack 채널 멤버로 정한다. 공개 Slack 채널은 워크스페이스 전체로 적는다.
- 받은 글의 Slack 표기(링크, Slack 채널, 멘션)는 사람이 읽는 글로 풀어서 넘긴다.
- 답은 Slack 표기로 해석되지 않게 이스케이프한다. 비서의 답이 Slack 채널 전체를 부르거나 누군가를 멘션하지 않는다.
- 긴 답은 줄바꿈에서 나눠 여러 메시지로 보낸다.
- Slack 채널에서 멘션받으면 그 메시지의 스레드에 답한다. DM은 대화에 바로 답하고, DM 스레드에서 온 말은 그 스레드에 답한다.
- 받은 봉투는 메시지를 넘기기 전에 확인 응답한다. Slack이 다시 보낸 메시지는 core가 메시지 id로 거른다.
- 연결이 끊기거나, 한동안 아무것도 오지 않거나, Slack이 끊겠다고 알리면 다시 연결한다. 잇따라 실패하면 기다리는 시간을 늘린다.
- 토큰이 더 이상 통하지 않을 때만 채널을 끝낸다.
- 보낸 메시지는 시간 초과로 실패해도 다시 보내지 않는다. 같은 답이 두 번 가는 것보다 낫다.
- 사람 이름은 Slack에서 잠깐만 물어 기억한다. 답이 없으면 사용자 id를 이름으로 쓴다.
- 연동은 주인의 사용자 토큰으로 MCP 도구에서 한다. 주인 권한으로 Slack 채널과 DM을 찾아 읽고, 주인 이름으로 보낸다.

## 미정

- Slack 연동에 Slack의 MCP 서버를 쓸지, 직접 만들지
- 설정창에서 Slack을 설정하는 방법
