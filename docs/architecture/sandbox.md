# 샌드박스

dotori의 모델이 실행하는 셸 명령을 어떤 샌드박스에서 돌리는지 정한다.

## 배경

셸 명령은 주인 계정으로 돌아서, 막지 않으면 dotori 폴더의 금고와 대화 기록과 브라우저 로그인을 그대로 읽을 수 있다. 주인이 명령마다 허락하더라도 명령이 무엇을 읽는지 다 알 수는 없다.

## 내용

- 메인 세션과 LLM API 실행기 서브 세션의 셸 명령만 샌드박스에서 돌린다.
- Claude Code와 Codex 서브 세션은 샌드박스에 넣지 않고 지금처럼 돌린다.
- 샌드박스는 dotori 폴더를 숨기고, 그 안의 작업 폴더만 다시 연다.
- 작업 폴더는 지금 자리에 그대로 둔다.
- 그 밖의 폴더와 인터넷, 키체인, D-Bus는 그대로 쓴다.
- 금고의 키를 두는 곳은 바꾸지 않는다.
- macOS는 `sandbox-exec`에 dotori가 만든 프로필을 주어 처음부터 켠다.
- macOS 프로필은 dotori 폴더의 모든 파일 작업을 막고, 작업 폴더만 다시 연다.
- macOS 프로필은 작업 폴더와 dotori 폴더 위의 폴더들을 지우거나, 옮기거나, 새로 만들지 못하게 한다.
- macOS 프로필은 샌드박스 밖 프로세스의 인자와 환경 변수와 그 밖의 세부 정보를 읽지 못하게 한다.
- macOS 프로필은 같은 샌드박스 안의 프로세스, 곧 명령 자신과 그 자식의 정보는 그대로 읽게 둔다.
- macOS 샌드박스 안에서는 `ps`가 실행되지 않는다.
- macOS에서 샌드박스가 돌지 않으면 명령을 실행하지 않는다.
- 작업 폴더가 링크이거나 dotori 폴더 밖을 가리키면 샌드박스가 있는 PC에서는 명령을 실행하지 않는다.
- 파일 도구도 그때는 아무 파일도 다루지 않는다.
- 파일 도구는 파일을 연 뒤 연 파일의 실제 자리를 다시 검사한다.
- 새 파일은 실제 자리를 검사한 폴더 안에 링크를 따르지 않고 만든다.
- Linux는 bubblewrap으로 dotori 폴더 위에 빈 tmpfs를 얹고 작업 폴더를 다시 붙인다.
- Linux 샌드박스는 새 PID 네임스페이스와 새 `/proc`을 써서 dotori의 프로세스를 보지 못하게 한다.
- Linux 샌드박스는 dotori가 끝나면 함께 끝난다.
- Linux 샌드박스의 명령은 터미널과 다른 세션으로 돈다.
- Linux에서는 bubblewrap이 주인 계정으로 돌 때만 켜진다.
- bubblewrap은 dotori가 설치한 사본과 시스템 폴더의 것만 쓰고, PATH에서 찾지 않는다.
- 그 프로그램과 위의 폴더가 모두 root의 것이고 다른 사용자가 바꿀 수 없을 때만 쓴다.
- 데몬은 명령을 돌릴 때마다 샌드박스가 도는지 보고, 한 번 돌면 그것을 계속 쓴다.
- 샌드박스가 도는지 보는 일에는 시간 제한을 둔다.
- `dotori sandbox install`은 root로 돌며 Linux에 샌드박스 환경을 설치한다.
- bubblewrap이 없으면 배포판의 패키지 관리자로 설치하고, 아는 패키지 관리자가 없으면 실패로 알린다.
- AppArmor가 사용자 네임스페이스를 막는 Linux에서는 bubblewrap을 dotori만 쓰는 고정 경로에 복사하고, 그 경로에만 사용자 네임스페이스를 허락하는 AppArmor 프로필을 넣는다.
- 그 프로필은 Ubuntu의 `bwrap-userns-restrict`를 따라, 사본이 띄우는 프로그램을 권한도 사용자 네임스페이스도 없는 하위 프로필로 옮긴다.
- 사본은 root와 설치를 부탁한 주인의 그룹만 실행할 수 있다.
- 사본은 패키지 업데이트를 따라가지 않는다.
- `dotori sandbox install`을 다시 실행하면 사본을 새로 복사한다.
- 커널이 사용자 네임스페이스를 아예 끈 Linux에서는 설정을 바꾸지 않고 실패로 알린다.
- 설정창은 관리자 확인이 필요하면 `pkexec`로 `dotori sandbox install`을 실행한다.
- dotori 실행 파일과 그 위의 폴더가 모두 root의 것이고 다른 사용자가 바꿀 수 없을 때만 `pkexec`로 실행한다.
- 그렇지 않으면 관리자 확인 창을 띄우지 않고, 이유와 직접 실행할 명령을 보여 준다.
- dotori가 root로 돌면 관리자 확인 없이 바로 실행한다.
- 설치하지 못하면 이유와 함께 터미널에서 직접 실행할 `sudo` 명령을 보여 준다.
- Windows에는 샌드박스가 없고, 창에도 샌드박스를 적지 않는다.
- 샌드박스를 쓸 수 없으면 명령은 지금처럼 주인의 허락을 받아 샌드박스 없이 돈다.
- 허락 카드는 창에서도 채팅방에서도 명령이 샌드박스 안에서 도는지 적지 않는다.
- 설정창의 카드는 확인하는 동안 확인 중이라고 적고, 샌드박스가 돌지 않아 명령을 막았으면 그렇다고 적는다.
- 샌드박스는 명령이 홈 폴더에 심어 둔 코드를 나중에 다른 프로그램이 실행하는 것은 막지 않는다.
- 샌드박스는 명령이 D-Bus 세션 버스나 launchd 같은 샌드박스 밖의 서비스에게 대신 실행해 달라고 하는 것도 막지 않는다.
- Linux의 `systemd-run --user`는 세션 버스로 샌드박스 밖에서 명령을 띄울 수 있다.
