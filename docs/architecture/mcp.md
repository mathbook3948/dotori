# MCP

에이전트가 쓰는 도구를 어떻게 제공하는지 정한다.

## 배경

fetch_url, browser 같은 도구를 직접 만들어서, 어느 실행기에서도 같은 도구를 쓰게 한다. 브라우저 로그인 상태도 유지해야 한다.

## 내용

- MCP 서버에는 모든 실행기가 함께 쓰는 공통 도구만 둔다.
- 브라우저와 fetch_url처럼 로그인 세션 같은 상태를 함께 유지해야 하는 도구다.
- 파일과 셸 같은 기본 도구는 MCP 서버에 두지 않는다.
- 각 실행기가 자체로 갖는다.
- MCP 서버는 dotori가 직접 만든다.
- 앱이 서버 프로세스를 하나만 띄우고, 모든 세션이 HTTP로 같이 쓴다.
- 서버가 브라우저와 브라우저 프로필을 계속 갖고 있어서 로그인 상태가 유지된다.
- 서버는 `dotori mcp` 프로세스다.
- 데몬이 자식으로 띄우고, 데몬이 끝나면 함께 끝난다.
- 서버가 죽으면 다음 도구 호출 전에 다시 띄운다.
- 서버는 127.0.0.1에서 Streamable HTTP로 답하고, 토큰이 맞는 요청만 받는다.
- 다른 사이트의 웹 페이지가 보낸 요청은 거절한다.
- 메인 세션은 시작할 때 서버의 도구 목록을 한 번 받아 쓴다.
- 서버를 못 띄우면 도구 없이 돈다.
- fetch_url는 웹 페이지를 Markdown으로 바꿔 돌려주고, 긴 페이지는 나눠서 돌려준다.
- fetch_url는 공개 주소만 가져온다.
- 이 PC와 내부망 주소는 페이지가 리다이렉트로 이끌어도 가져오지 않는다.
- 프록시를 쓰면 이름 조회는 프록시가 한다.
- 그때 fetch_url는 URL에 적힌 주소만 검사한다.
- 브라우저 도구는 [브라우저](browser.md)에서 정한다.
- 주인의 외부 서비스 연동은 모두 MCP 도구로 한다.
- 주인 계정 권한을 쓴다.
- API가 없는 서비스는 주인이 로그인해 둔 브라우저로 연동한다.
- 다른 곳에서 만든 MCP 서버도 연동으로 붙일 수 있다.
- 외부 MCP 서버는 dotori MCP 서버가 연결해서 중계한다.
- 모든 세션은 dotori MCP 서버 하나만 본다.
- 다른 사람을 향한 행동의 확인은 중계에서 지킨다.
- 외부 도구도 같은 규칙을 따른다.
- 외부 서버는 설정의 `[[mcp]]`에 이름과 함께 HTTP 주소나 실행 명령으로 적는다.
- 토큰은 이름만 적고, 값은 같은 이름의 환경 변수나 vault에서 읽는다.
- 실행 명령으로 띄운 서버는 비밀값이 든 환경 변수를 물려받지 않고, 자기 토큰 하나만 그 이름으로 받는다.
- 외부 도구는 `서버이름__도구이름`으로 보인다.
- `tools`를 적으면 그 도구만 보인다.
- 도구는 모두 모델에 보여 준다.
- 너무 많으면 주인이 서버마다 `tools`로 줄인다.
- 외부 서버의 로그인은 토큰으로만 한다.
- dotori가 OAuth 로그인을 대신하지 않는다.
- 토큰을 환경 변수로 두면 PC마다 두고, vault에 두면 묶인 PC와 함께 쓴다.
- 다른 사람을 향한 외부 도구는 주인이 `[[mcp]]`의 `confirm`에 도구 이름으로 적는다.
- `"*"`는 그 서버의 모든 도구다.
- 적힌 도구는 부를 때마다 주인의 허락을 기다린다.
- `confirm`이 있는 서버는 dotori MCP 서버가 중계하지 않고 데몬이 직접 연결한다.
- 그래서 메인 세션만, 허락을 거쳐서만 그 서버의 도구를 쓴다.
- 서브 세션은 그 서버를 보지 못한다.
- `confirm`에 적었지만 어느 서버에도 없는 도구 이름은 시작할 때 알리고, 그 서버의 모든 도구가 허락을 기다리게 한다.
- 잘못 적은 이름이 있어도 확인은 빠지지 않는다.
- `[[mcp]]` 이름은 겹치지 않는다.
- 같은 이름의 두 번째 서버는 빼고 알린다.
- `confirm`이 있는 서버의 토큰이 든 환경 변수는 코딩 에이전트 서브 세션에 넘기지 않는다.
- dotori MCP 서버는 시작할 때 외부 서버에 연결해 도구 목록을 받는다.
- 연결하지 못한 서버는 빼고 시작한다.
- 외부 서버와 연결이 끊기면 다음 호출 때 다시 연결한다.
- 실행 명령으로 띄운 서버는 dotori MCP 서버가 끝나면 함께 끝난다.
- 서버는 앱을 통해 사용자에게 요청을 보낼 수 있다.
- 요청을 보낸 도구는 사용자를 기다리지 않고 결과를 바로 돌려준다.
- 주인에게 닿는 브라우저 도구는 MCP 서버의 두 번째 주소에서만 내놓고, 그 주소와 토큰은 데몬만 안다.
- 코딩 에이전트와 서브 세션은 그 도구를 보지 못한다.
- 채팅창의 카드로 주인에게 칸을 채우게 하거나 로그인을 묻는 도구만 주인의 답을 기다린다.
- 메인 세션은 그 도구를 기다리지 않고, 결과를 `decision` 채널로 받는다.
