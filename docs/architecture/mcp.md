# MCP

에이전트가 쓰는 도구를 어떻게 제공하는지 정한다.

## 배경

webfetch, browser 같은 도구를 직접 만들어서, 어느 실행기에서도 같은 도구를 쓰게 한다. 브라우저 로그인 상태도 유지해야 한다.

## 내용

- MCP 서버에는 모든 실행기가 함께 쓰는 공통 도구만 둔다. 브라우저와 webfetch처럼 로그인 세션 같은 상태를 함께 유지해야 하는 도구다.
- 파일과 셸 같은 기본 도구는 MCP 서버에 두지 않는다. 각 실행기가 자체로 갖는다.
- MCP 서버는 dotori가 직접 만든다. 앱이 서버 프로세스를 하나만 띄우고, 모든 세션이 HTTP로 같이 쓴다.
- 서버가 브라우저와 브라우저 프로필을 계속 갖고 있어서 로그인 상태가 유지된다.
- 서버는 `dotori mcp` 프로세스다. 데몬이 자식으로 띄우고, 데몬이 끝나면 함께 끝난다. 서버가 죽으면 다음 도구 호출 전에 다시 띄운다.
- 서버는 127.0.0.1에서 Streamable HTTP로 답하고, 토큰이 맞는 요청만 받는다. 다른 사이트의 웹 페이지가 보낸 요청은 거절한다.
- 메인 세션은 시작할 때 서버의 도구 목록을 한 번 받아 쓴다. 서버를 못 띄우면 도구 없이 돈다.
- webfetch는 웹 페이지를 Markdown으로 바꿔 돌려주고, 긴 페이지는 나눠서 돌려준다.
- webfetch는 공개 주소만 가져온다. 이 PC와 내부망 주소는 페이지가 리다이렉트로 이끌어도 가져오지 않는다.
- 프록시를 쓰면 이름 조회는 프록시가 한다. 그때 webfetch는 URL에 적힌 주소만 검사한다.
- 브라우저 도구는 [브라우저](browser.md)에서 정한다.
- 주인의 외부 서비스 연동은 모두 MCP 도구로 한다. 주인 계정 권한을 쓴다.
- API가 없는 서비스는 주인이 로그인해 둔 브라우저로 연동한다.
- 다른 곳에서 만든 MCP 서버도 연동으로 붙일 수 있다.
- 외부 MCP 서버는 dotori MCP 서버가 연결해서 중계한다. 모든 세션은 dotori MCP 서버 하나만 본다.
- 다른 사람을 향한 행동의 확인은 중계에서 지킨다. 외부 도구도 같은 규칙을 따른다.
- 서버는 앱을 통해 사용자에게 요청을 보낼 수 있다. 요청을 보낸 도구는 사용자를 기다리지 않고 결과를 바로 돌려준다.

## 미정

- 외부 MCP 서버의 로그인과, 여러 PC에서 그 토큰을 나누는 방법
- 외부 도구 중 어떤 것이 다른 사람을 향한 행동인지 가리는 방법
- 도구가 많을 때 필요한 것만 모델에 보여 주는 방법
