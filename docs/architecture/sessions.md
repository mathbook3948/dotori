# 세션

주인이 어디서 비서와 말하고, 대화를 어떤 세션으로 나누는지 정한다.

## 배경

dotori는 주인 한 사람의 비서다. 주인이 어디서 말을 걸든 같은 비서와 이어져야 하고, 다른 사람이 비서에게 일을 시키면 비서가 아니라 팀 봇이 된다.

## 내용

- 외부 연결은 연동과 채널 두 가지다.
- 연동은 주인 계정 권한의 MCP 도구로 주인의 서비스를 읽고 대신 행동한다. 자세한 내용은 [MCP](mcp.md)에 있다.
- 채널은 주인이 비서와 말하는 곳이다. 채팅창과, 주인이 설정에서 고른 Slack 워크스페이스, Telegram 봇, Discord 봇이 채널이다.
- 채널 안의 대화 자리는 방이라고 부른다. DM, Slack 채널, 그룹방이 방이다.
- 채널에서는 DM이든 다른 사람이 있는 방이든 주인의 메시지만 받고, 그 방에 답한다.
- 다른 사람의 메시지는 받지 않는다. 다른 사람의 말은 주인이 요청해서 읽을 때만 참고 자료로 들어오고, 지시로 따르지 않는다.
- 세션은 메인 세션과 서브 세션 두 가지다.
- 메인 세션은 주인과의 대화 하나다. 주인이 어느 채널에서 말하든 같은 메인 세션으로 이어진다.
- 서브 세션은 메인 세션이 일을 맡길 때 만든다. 메인 세션은 결과만 받는다. 다른 사람은 서브 세션을 만들 수 없다.
- 채널은 메시지마다 그 방을 볼 수 있는 참가자를 붙인다. 사람이 많으면 일부 이름과 전체 수를 붙이고, 누구나 읽을 수 있는 방은 그 범위 전체로 적는다. 공개 Slack 채널이면 워크스페이스 전체다.
- 참가자가 주인뿐이면 모든 기억을 써서 답한다. 다른 사람이 있으면 그 사람들이 봐도 되는 내용만 답하고, 사적인 내용은 주인만 있는 방으로 따로 보낸다.
- 주인이 내용까지 정해서 시킨 일은 바로 한다.
- 비서가 내용을 정하거나 스스로 시작하는 일 중 다른 사람을 향한 행동은 주인에게 확인받는다.
- 채널은 Telegram을 먼저 붙인다. HTTP만으로 받을 수 있어서다. Discord는 Gateway 연결이 필요해서 그다음이다. Telegram은 [Telegram 연결](telegram.md)에 있다.
- 주인이 말을 건 방에 답하는 것은 다른 사람을 향한 행동이 아니다. 다른 사람이 읽어도 주인에게 하는 답이다.
- 확인받는 행동은 주인이 설정에서 고른 연동 도구의 호출이다. 어떤 도구가 다른 사람을 향하는지는 주인이 정한다.
- 확인은 채팅창의 카드로 받는다. 카드는 도구와 넘길 내용을 보여 주고, 주인이 허락을 누를 때만 호출한다. 모델은 주인 대신 허락할 수 없다.
- 확인을 기다리는 동안 메인 세션은 다른 일을 계속한다. 주인이 정하면 그 결과가 `decision` 채널로 메인 세션에 들어간다. 주인의 말이 아니라 도구가 돌려준 자료로 다루고, 메모와 루틴을 바꿀 권한도 주지 않는다.
- 기다리는 호출은 메인 세션을 맡은 PC가 갖는다. dotori가 다시 시작하거나 메인 세션이 다른 PC로 옮겨 호출이 사라지면, 주인의 답에는 "이제 할 수 없어요"를 보여 주고 메인 세션에 알린다.
- 결과는 모델에게 주인의 메시지가 아닌 `decided_call`로 보인다.
- 같은 호출에 대한 두 번째 답은 무시한다. 창은 누른 즉시 버튼 대신 "처리하는 중이에요"를 보여 준다.
- 카드는 긴 값을 줄여 보여 주고, "전체 보기"로 모두 펼친다. 연달은 빈 줄은 하나로 줄인다.
- 메인 세션을 맡은 PC가 호출 중에 바뀌면, 그 결과는 이 PC가 다시 메인 세션을 맡을 때 전해진다.
- 코딩 에이전트 서브 세션은 주인과 같은 사용자로 돌기 때문에 창의 연결 파일과 데몬의 환경을 읽을 수 있다. 서브 세션 격리를 정할 때까지 확인은 메인 세션의 모델을 막는 장치이고, 코딩 에이전트까지 막지는 못한다.
