# 브라우저

에이전트가 쓰는 브라우저를 어떻게 띄우고, 모델과 사용자가 어떻게 움직이는지 정한다.

## 배경

비서는 사용자가 로그인한 사이트에서 일해야 하고, 그 로그인 상태는 여러 PC와 모든 세션이 함께 쓰는 봇 브라우저 하나에 있다. 사이트가 봇을 막아도 일할 수 있어야 한다.

## 내용

- 브라우저는 dotori 전용이다. 사용자가 설치한 브라우저는 쓰지 않는다.
- 공식 Chrome for Testing 빌드를 처음 쓸 때 받고, 해시를 확인해 dotori 폴더에 둔다.
- 해시는 Google 저장소가 내려받기 응답에 알려 주는 MD5다.
- 브라우저는 MCP 서버가 뜰 때 백그라운드로 받는다. 받는 동안 브라우저 도구는 기다리지 않고 받는 중이라고 답한다.
- dotori는 설치된 브라우저를 찾지 않는다. 설정에 경로를 적을 때만 다른 브라우저를 쓴다.
- 창 없이 돌 때도 페이지에는 창이 있는 Chrome의 사용자 에이전트를 알린다.
- 브라우저는 DevTools 프로토콜로 움직인다. 프로토콜 클라이언트는 직접 만든다.
- 브라우저는 처음 쓸 때 띄우고, 죽었으면 다음에 다시 띄운다. dotori 폴더 안의 프로필을 써서 로그인이 남는다.
- 브라우저는 자기 창 없이 돈다. 사용자는 채팅창의 브라우저 화면으로 본다.
- 모델은 Playwright 형태의 JS 코드를 짜서 브라우저를 움직인다.
- 모델의 코드는 dotori가 Rust로 직접 만든 JS 인터프리터에서 돈다. 다른 JS 엔진을 넣지 않는다.
- 인터프리터는 페이지 밖의 흐름만 실행한다. 페이지 안에서 돌릴 코드는 브라우저가 실행한다.
- 인터프리터는 모델이 짜는 Playwright 코드를 제대로 실행하는 것만 목표로 한다. 그 밖의 JS는 지원하지 않는다.
- 지원하지 않는 문법은 이름을 들어 거절해서, 모델이 다른 방법으로 다시 짜게 한다.
- 브라우저 도구는 코드를 돌리는 `browser_run`과 페이지를 읽는 `browser_read` 두 가지다.
- 페이지 요약의 번호 `[n]`은 코드에서 `ref=n` 로케이터로 쓴다.
- 요소를 쓰는 동작은 요소가 보일 때까지 기다리고, 로케이터가 여러 요소를 가리키면 거절한다.
- 코드가 찍은 줄과 돌려준 값을 먼저 보여 주고, 그 뒤에 페이지 요약을 붙인다. 실패해도 페이지 요약을 붙인다.
- 코드는 정해진 단계 수와 시간 안에서만 돈다.
- 페이지 요약은 누를 수 있는 요소에 번호와 상태를 붙이고, 중요한 내용을 앞에 둔다.
- 브라우저로 여는 주소는 webfetch와 같은 규칙으로 검사한다. 막힌 주소로 가는 문서 요청은 브라우저가 보내기 전에 막는다. 페이지가 스스로 불러오는 자원은 막지 않는다.
- 비밀번호는 받지도 저장하지도 않는다. 로그인은 사용자가 직접 한다.
- 봇 프로필은 비밀번호를 저장하지 않는다.
- 비밀번호 칸의 값은 모델에게 보여주지 않는다.
- 페이지의 alert, confirm, prompt 창은 띄우지 않는다. confirm은 거절로 답한다. 페이지의 함수를 바꾸지 않고 브라우저 쪽에서 처리한다.
- 봇 탐지를 피한다. 자동화 표시를 끄고, 페이지가 볼 수 있는 곳에 dotori의 흔적을 남기지 않는다.
- dotori가 페이지에서 돌리는 스크립트는 페이지와 분리된 실행 공간에서 돈다.
- 채팅창은 봇 브라우저의 화면을 실시간으로 보여주고, 에이전트가 누르는 곳을 표시한다.
- 채팅창은 MCP 서버가 따로 연 화면 채널에 바로 붙는다. 주소와 토큰은 사용자만 읽는 파일에 둔다.
- 화면은 보는 창이 있을 때만 전송한다.
- 채팅창의 브라우저는 대화와 나란한 탭이다. 넘겨받기를 부탁받으면 탭에 표시가 생긴다.
- 주인이 넘겨받은 동안 브라우저 도구는 기다리지 않고 거절한다.
- 보는 창이 모두 닫히면 브라우저는 dotori에게 돌아간다.
- 붙여넣기는 주인 PC의 클립보드 글을 입력으로 보낸다.
- 사용자는 브라우저를 넘겨받아 직접 조작하고, 다 쓰면 돌려준다. 넘겨받은 동안 에이전트는 브라우저를 쓰지 않는다.
- 로그인이 필요하면 에이전트는 앱으로 사용자에게 넘겨받기를 요청한다.
- 브라우저 화면은 브라우저가 그린 화면을 전송받아 그리고, 마우스와 키보드 입력을 브라우저로 보낸다.
- 글자 입력은 OS 입력기가 조합한 결과를 보낸다. 특정 언어에 맞춘 처리를 두지 않는다.
- 화면 전송에 나오지 않는 드롭다운, 날짜 선택, 파일 선택, 인증 창은 채팅창이 직접 띄운다.
- 위치, 알림, 카메라 같은 권한 요청은 묻지 않고 거절한다. 그런 권한이 꼭 필요한 일은 연동 도구로 한다.
- 페이지 요약은 같은 출처의 iframe 안 글과 요소도 읽는다. iframe 안 요소에는 번호를 붙이지 않고, 다른 사이트의 iframe은 이름만 적는다.
- 새 탭이나 팝업으로 열린 페이지는 화면과 모델이 함께 따라간다.
- Chromium을 직접 고치지 않는다. Chrome for Testing을 그대로 쓰고, 흔적은 DevTools 프로토콜로만 지운다.
- 봇 탐지 때문에 창을 띄우지 않는다. 막히면 주인이 넘겨받아 푼다.
- 모델에게는 페이지 그림을 보여 주지 않는다. 글 요약과 요소 번호로 다룬다.
- 브라우저는 PC의 채팅창에서만 넘겨받는다. 폰에서는 넘겨받지 않는다.
- 드롭다운과 날짜, 시간, 색 칸은 주인이 누를 때 그 자리의 요소를 확인해, 브라우저 대신 채팅창이 고르기 카드를 띄운다. 고른 값은 페이지에 넣고 input과 change 이벤트를 보낸다.
- 파일 선택은 브라우저의 대화상자 대신 채팅창이 주인 PC의 파일 대화상자를 연다.
- 새 창이 열리면 화면과 주인의 입력은 그 창을 따라가고, 창이 닫히면 원래 페이지로 돌아온다. 새 창에도 같은 주소 검사를 한다.
- 새 창으로 열린 로그인 팝업도 브라우저 화면에서 보여준다.
