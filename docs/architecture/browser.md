# 브라우저

에이전트가 쓰는 브라우저를 어떻게 띄우고, 모델과 사용자가 어떻게 움직이는지 정한다.

## 배경

비서는 사용자가 로그인한 사이트에서 일해야 하고, 그 로그인 상태는 여러 PC와 모든 세션이 함께 쓰는 봇 브라우저 하나에 있다. 사이트가 봇을 막아도 일할 수 있어야 한다.

## 내용

- 브라우저는 dotori 전용이다.
- 사용자가 설치한 브라우저는 쓰지 않는다.
- 공식 Chrome for Testing 빌드를 처음 쓸 때 받고, 해시를 확인해 dotori 폴더에 둔다.
- 해시는 Google 저장소가 내려받기 응답에 알려 주는 MD5다.
- 브라우저는 MCP 서버가 뜰 때 백그라운드로 받는다.
- 받는 동안 브라우저 도구는 기다리지 않고 받는 중이라고 답한다.
- dotori는 설치된 브라우저를 찾지 않는다.
- 설정에 경로를 적을 때만 다른 브라우저를 쓴다.
- 창 없이 돌 때도 페이지에는 창이 있는 Chrome의 사용자 에이전트를 알린다.
- 브라우저는 DevTools 프로토콜로 움직인다.
- macOS와 Linux에서는 DevTools를 브라우저의 파이프로만 주고받고, 이 PC의 다른 프로그램이 붙을 수 있는 포트를 열지 않는다.
- Windows에서는 브라우저가 고른 127.0.0.1의 포트로 주고받는다.
- 브라우저를 띄운 MCP 서버가 끝나면 파이프가 닫혀 브라우저도 끝나고, 다음에 띄우는 브라우저는 앞의 것이 비킬 때까지 잠시 기다린다.
- 프로토콜 클라이언트는 직접 만든다.
- 브라우저는 처음 쓸 때 띄우고, 죽었으면 다음에 다시 띄운다.
- dotori 폴더 안의 프로필을 써서 로그인이 남는다.
- 디스크 캐시도 프로필 폴더 안에 둔다.
- 브라우저는 자기 창 없이 돈다.
- 사용자는 채팅창의 브라우저 화면으로 본다.
- 모델은 Playwright 형태의 JS 코드를 짜서 브라우저를 움직인다.
- 모델의 코드는 dotori가 Rust로 직접 만든 JS 인터프리터에서 돈다.
- 다른 JS 엔진을 넣지 않는다.
- 인터프리터는 페이지 밖의 흐름만 실행한다.
- 페이지 안에서 돌릴 코드는 브라우저가 실행한다.
- 인터프리터는 모델이 짜는 Playwright 코드를 제대로 실행하는 것만 목표로 한다.
- 그 밖의 JS는 지원하지 않는다.
- 지원하지 않는 문법은 이름을 들어 거절해서, 모델이 다른 방법으로 다시 짜게 한다.
- 모든 세션이 쓰는 브라우저 도구는 코드를 돌리는 `run_in_browser`과 페이지를 읽는 `read_page` 두 가지다.
- 페이지 요약의 번호 `[n]`은 코드에서 `ref=n` 로케이터로 쓴다.
- 요소를 쓰는 동작은 요소가 보일 때까지 기다리고, 로케이터가 여러 요소를 가리키면 거절한다.
- 코드가 찍은 줄과 돌려준 값을 먼저 보여 주고, 그 뒤에 페이지 요약을 붙인다.
- 실패해도 페이지 요약을 붙인다.
- 코드는 정해진 단계 수와 시간 안에서만 돈다.
- 페이지 요약은 누를 수 있는 요소에 번호와 상태를 붙이고, 중요한 내용을 앞에 둔다.
- 브라우저로 여는 주소는 fetch_url와 같은 규칙으로 검사한다.
- `file://` 주소는 열지 않는다.
- 막힌 주소로 가는 문서 요청은 브라우저가 보내기 전에 막는다.
- 페이지가 스스로 불러오는 자원은 막지 않는다.
- 주인이 연동한 사이트의 계정은 금고에 둔다.
- 대화하는 AI는 계정의 아이디를 볼 수 있고, 비밀번호와 인증번호는 보지 않는다.
- 봇 프로필은 비밀번호를 저장하지 않는다.
- 비밀번호 칸의 값은 모델에게 보여주지 않는다.
- 페이지의 alert, confirm, prompt 창은 띄우지 않는다.
- confirm은 거절로 답한다.
- 페이지의 함수를 바꾸지 않고 브라우저 쪽에서 처리한다.
- 봇 탐지를 피한다.
- 자동화 표시를 끄고, 페이지가 볼 수 있는 곳에 dotori의 흔적을 남기지 않는다.
- dotori가 페이지에서 돌리는 스크립트는 페이지와 분리된 실행 공간에서 돈다.
- 채팅창은 봇 브라우저의 화면을 실시간으로 보여주고, 에이전트가 누르는 곳을 표시한다.
- 채팅창은 MCP 서버가 따로 연 화면 채널에 바로 붙는다.
- 주소와 토큰은 사용자만 읽는 파일에 둔다.
- 화면은 보는 창이 있을 때만 전송한다.
- 채팅창의 브라우저는 대화와 나란한 탭이다.
- 넘겨받기를 부탁받으면 탭에 표시가 생긴다.
- 주인이 넘겨받은 동안 브라우저 도구는 기다리지 않고 거절한다.
- 보는 창이 모두 닫히면 브라우저는 dotori에게 돌아간다.
- 붙여넣기는 주인 PC의 클립보드 글을 입력으로 보낸다.
- 사용자는 브라우저를 넘겨받아 직접 조작하고, 다 쓰면 돌려준다.
- 넘겨받은 동안 에이전트는 브라우저를 쓰지 않는다.
- 로그인이 필요하면 에이전트는 금고의 계정으로 로그인하거나, 채팅창의 카드로 주인에게 로그인 칸을 채워 달라고 한다.
- 그래도 안 되는 일은 앱으로 사용자에게 넘겨받기를 요청한다.
- 브라우저 화면은 브라우저가 그린 화면을 전송받아 그리고, 마우스와 키보드 입력을 브라우저로 보낸다.
- 글자 입력은 OS 입력기가 조합한 결과를 보낸다.
- 특정 언어에 맞춘 처리를 두지 않는다.
- 화면 전송에 나오지 않는 드롭다운, 날짜 선택, 파일 선택, 인증 창은 채팅창이 직접 띄운다.
- 위치, 알림, 카메라 같은 권한 요청은 주인에게 묻지 않는다.
- 창 없는 Chrome이 기본으로 거절하는 대로 둔다.
- 그런 권한이 꼭 필요한 일은 연동 도구로 한다.
- 페이지 요약은 같은 출처의 iframe 안 글과 요소도 읽는다.
- iframe 안 요소에는 번호를 붙이지 않고, 읽을 수 없는 iframe은 이름만 적는다.
- Chromium을 직접 고치지 않는다.
- Chrome for Testing을 그대로 쓰고, 흔적은 DevTools 프로토콜로만 지운다.
- 창을 띄우지 않는다.
- 막히면 주인이 넘겨받아 푼다.
- 모델에게는 페이지 그림을 보여 주지 않는다.
- 글 요약과 요소 번호로 다룬다.
- 브라우저는 PC의 채팅창에서만 넘겨받는다.
- 폰에서는 넘겨받지 않는다.
- 드롭다운과 날짜, 시간, 색 칸은 주인이 누를 때 그 자리의 요소를 확인해, 브라우저 대신 채팅창이 고르기 카드를 띄운다.
- 고른 값은 페이지에 넣고 input과 change 이벤트를 보낸다.
- 파일 선택은 브라우저의 대화상자 대신 채팅창이 주인 PC의 파일 대화상자를 연다.
- 새 창이 열리면 화면과 주인의 입력은 그 창을 따라가고, 창이 닫히면 원래 페이지로 돌아온다.
- 새 창에도 같은 주소 검사를 한다.
- 새 창으로 열린 로그인 팝업도 브라우저 화면에서 보여준다.
- 사이트가 HTTP 인증을 물으면 채팅창이 아이디와 비밀번호를 받는 로그인 카드를 띄운다.
- 넘겨받지 않아도 답할 수 있다.
- 로그인 카드에 넣은 값은 카드가 물은 그 요청에만 넘기고 기록하지 않는다.
- 기다리는 로그인마다 번호를 붙여, 다른 요청이 끼어들어도 답이 엉뚱한 사이트로 가지 않는다.
- 주인이 한동안 답하지 않으면 그 로그인만 취소한다.
- 같은 요청이 다시 물으면 아이디나 비밀번호가 틀렸다고 알린다.
- 주인에게 닿는 브라우저 도구(`ask_owner_in_browser`, `ask_owner_to_fill`, `fill_login`)는 메인 세션만 쓴다.
- 이 도구들은 코딩 에이전트가 붙는 MCP 주소에 없고, 데몬만 아는 다른 주소와 토큰으로만 부른다.
- 서브 세션은 이 도구들을 보지 못한다.
- 모델은 `ask_owner_to_fill`로 페이지 요약의 번호에 이름을 붙여 채울 카드를 띄운다.
- 카드는 글 칸, 체크 칸, 누를 버튼 하나, 링크로 이뤄진다.
- 글 칸은 보통 글, 비밀 글, 인증번호 중 하나다.
- 카드는 HTTPS 페이지에만 띄운다.
- dotori는 카드를 띄우기 전에 번호마다 요소가 지금 페이지에 있는지 확인한다.
- 요소가 맞는 종류가 아니면 거절한다.
- 비밀 글 칸은 비밀번호 칸이어야 한다.
- 비밀번호 칸을 보통 글 칸으로 부르면 거절한다.
- 칸과 버튼이 폼 안에 있으면 모두 같은 폼에 있어야 한다.
- 그 폼이 보내는 곳은 페이지와 같은 출처여야 한다.
- 보내는 곳과 방식은 버튼의 `formaction`과 `formmethod`까지 보고, 폼 안의 칸 이름에 가려지지 않게 읽는다.
- 비밀 글이나 인증번호 칸이 있는 폼이 POST가 아닌 방식으로 보내면 거절한다.
- 모델의 코드가 돈 문서에는 카드를 띄우지 않고 계정도 채우지 않는다.
- 모델은 `read_page`에 주소를 줘서 그 페이지를 다시 연 뒤에 카드를 띄운다.
- `run_in_browser`가 도는 동안 열린 문서도 코드가 돈 문서로 센다.
- 코드가 끝나거나 시간이 다 되면 그때의 문서도 코드가 돈 문서로 센다.
- 모델의 코드는 한 번만 보내고, 페이지가 바뀌었다고 새 문서에 다시 보내지 않는다.
- 문서는 로더 id로 구별한다.
- 카드가 주인을 기다리는 동안 `run_in_browser`는 돌지 않는다.
- 브라우저에 다른 창이 열려 있으면 카드를 띄우지 않고, 그 창들을 닫고, 지금 문서를 코드가 돈 문서로 센다.
- 새 창이 붙으면 그때의 문서도 코드가 돈 문서로 센다.
- `read_page`에 주소를 주면 다른 창을 모두 닫은 뒤에 연다.
- 값을 넣기 직전에 다른 창이 열려 있으면 넣지 않는다.
- 서비스 워커가 다루는 문서에는 카드를 띄우지 않는다.
- 카드의 요소는 dotori가 요소의 백엔드 노드 번호로 기억한다.
- 카드를 확인하고 채우는 스크립트는 카드마다 새로 만든 실행 공간에서 돈다.
- 카드에는 브라우저가 지금 연 페이지의 호스트를 적고, 모델이 적은 주소는 쓰지 않는다.
- 모델은 카드에 값을 미리 넣지 못한다.
- 주인이 버튼을 누르면 dotori가 그 요소들에 직접 값을 넣는다.
- 비어 있는 칸은 건드리지 않는다.
- 칸이 받기에 너무 긴 값은 넣지 않고 거절한다.
- 값을 넣기 전에 커서가 그 칸에 갔는지 확인한다.
- 넣기 직전에 커서와 문서를 다시 확인한다.
- 넣은 뒤에 칸이 그 값을 받았는지 확인한다.
- 값을 넣은 뒤 체크 칸을 맞추고 버튼을 누른다.
- 주인이 링크를 누르면 칸은 채우지 않고 그 링크만 누른다.
- 카드를 띄운 뒤 문서가 바뀌었거나 코드가 돌았으면 아무것도 채우지 않는다.
- dotori가 비밀번호나 인증번호를 넣은 문서에서는 그 문서가 바뀔 때까지 모델의 코드가 돌지 않는다.
- 그 문서에서도 다른 주소로 옮기는 것은 된다.
- 버튼을 누른 뒤 잠시 기다려도 같은 문서면 dotori가 넣은 비밀번호와 인증번호 칸, 그동안 값이 바뀐 칸을 모두 비운다.
- 칸을 비우지 못하면 빈 페이지로 옮긴다.
- 페이지 요약은 비밀번호 칸과 dotori가 비밀번호나 인증번호를 넣은 칸의 값을 적지 않는다.
- 그 칸과 같은 폼의 칸, 값을 넣는 동안 값이 바뀐 칸의 값도 적지 않는다.
- 아이디 칸에 넣은 값은 가리지 않는다.
- 브라우저 도구의 결과에 dotori가 넣은 비밀번호나 인증번호, 지금 출처에 둔 계정의 비밀번호가 들어 있으면 결과를 통째로 주지 않는다.
- 그러면 그 값의 출처에서는 브라우저가 다시 시작할 때까지 `run_in_browser`와 `read_page`가 돌지 않는다.
- 짧은 값은 홀로 선 자리만 센다.
- 아이디는 결과에서 가리지 않는다.
- 모델에게는 누른 버튼이나 링크, 채운 칸의 이름, 그 뒤의 페이지만 알린다.
- `keep`을 주면 사이트 이름, 출처, 아이디 칸과 비밀번호 칸의 이름, 값을 금고에 둔다.
- 계정을 두는 카드에는 비밀 글 칸이 하나, 보통 글 칸이 많아야 하나 있다.
- 인증번호 칸의 값은 두지 않는다.
- 계정을 둘 때 그 로그인 페이지의 경로도 둔다.
- 금고에 자리가 없거나 계정 이름이 너무 길면 `keep` 카드를 띄우지 않는다.
- 한 출처에 계정을 여럿 둘 수 있고, 아이디마다 하나다.
- 같은 출처의 같은 아이디로 다시 두면 앞 계정을 바꾸고, 묻지 않기는 다시 꺼진다.
- 다른 아이디로 두면 계정이 하나 더 생긴다.
- `fill_login`은 지금 페이지의 출처와 같은 출처로 둔 계정만 채운다.
- `fill_login`은 모델이 이름 붙인 아이디 칸, 비밀번호 칸, 버튼을 카드와 같은 규칙으로 확인한다.
- `fill_login`의 아이디 칸은 글 입력 칸이어야 한다.
- 모델은 `account`에 아이디를 주어 계정을 고를 수 있다.
- 묻지 않기로 둔 계정이 하나 있고 지금 페이지가 그 계정의 로그인 경로면 `fill_login`은 묻지 않고 그 계정으로 채운다.
- 모델이 고른 계정이 묻지 않기로 둔 계정이고 지금 페이지가 그 로그인 경로여도 묻지 않는다.
- 묻지 않기로 둔 계정이 여럿이면 하나도 없는 것처럼 묻는다.
- 주인이 카드에서 묻지 않기를 켜면 그 페이지의 경로를 계정의 로그인 경로로 둔다.
- 그런 계정이 없으면 채팅창에서 먼저 묻는다.
- 모델이 고르지 않았고 계정이 여럿이면 주인이 카드에서 하나를 고른다.
- 묻지 않기는 출처마다 한 계정에만 붙고, 다른 계정에 켜면 그쪽으로 옮긴다.
- 주인이 답한 뒤 계정을 다시 읽어, 그사이 바뀌었거나 끊겼으면 채우지 않는다.
- 모델에게는 어느 사이트의 어느 아이디로 로그인했는지 알린다.
- 카드는 한 번에 하나이고, 새 카드가 앞 카드를 대신한다.
- 카드는 정해진 시간 동안만 답을 기다린다.
- 그 시간이 지나면 카드는 닫히고 아무것도 채우지 않는다.
- 카드 번호는 HTTP 인증 로그인의 번호와 섞이지 않는다.
- 카드는 브라우저를 맡은 PC의 채팅창에만 뜬다.
- 그 PC에 채팅창이 열려 있지 않으면 카드를 띄우는 도구는 바로 실패한다.
- 그때 모델은 주인에게 PC의 dotori 창에서 하자고 말한다.
- Telegram, Slack, Discord로 말하는 주인에게는 카드를 띄우지 않고 PC의 dotori 창에서 하자고 말한다.
- 주인이 카드에 적은 값은 화면 채널로 MCP 서버에만 간다.
- 그 값은 앱 채널, 대화 기록, 로그에 넣지 않는다.
- 모델이 받는 결과에는 비밀번호와 인증번호를 넣지 않는다.
- 메인 세션은 카드의 답을 기다리지 않는다.
- 카드가 어떻게 됐는지는 `decision` 채널로 받는다.
- 그 결과의 첫 줄은 창이 그리는 JSON이고, 그 뒤가 모델에게 하는 말이다.
- 주인의 허락을 기다리게 정해 둔 도구 목록은 주인에게 닿는 브라우저 도구에 적용하지 않는다.
- 같은 사이트에서 모델의 코드를 돌리면, 그 사이트가 볼 수 있는 것을 모델이 모두 못 보게 막을 수는 없다.

## 미정

- Windows에서는 브라우저의 DevTools 포트가, 샌드박스 없이 도는 코딩 에이전트에게는 화면 채널 파일이 주인과 같은 계정의 다른 프로세스에 열려 있다.
