# Discord 연결

Discord를 주인이 비서와 말하는 채널로 어떻게 쓰는지 정한다.

## 배경

주인은 Discord에서도 비서에게 말하고 싶다. Discord는 메시지를 Gateway WebSocket으로만 보내 주고, dotori는 공개 주소가 없는 개인 PC에서 돈다.

## 내용

- 채널은 봇으로 Gateway에 직접 연결해서 받는다.
- 공개 주소나 다른 서버가 필요 없다.
- 봇 토큰은 설정 파일에 쓰지 않는다.
- 설정에는 토큰의 이름만 적고, 값은 같은 이름의 환경 변수나 vault에서 읽는다.
- 설정 파일에 `[discord]` 항목이 있을 때만 채널을 연결한다.
- 토큰이나 주인이 없으면 Discord만 끄고 다른 채널과 데몬은 돈다.
- 주인은 설정에 적은 Discord 사용자 id 하나다.
- 다른 사람, 봇, 웹훅의 메시지와 전달된 메시지는 받지 않는다.
- 봇과의 DM에서는 주인의 모든 글을 받는다.
- 서버에서는 봇이나 봇의 역할을 멘션하거나 봇의 말에 답한 주인의 글만 받고, 멘션은 떼고 넘긴다.
- DM은 주인만 읽는 방이다.
- 서버의 채널은 멤버가 몇이든 서버 전체가 볼 수 있는 방으로 다룬다.
- 채널 권한이나 멤버 수로 좁히지 않는다.
- 서버에서 받은 말에는 그 메시지에 답장으로 답한다.
- 주인에게만 보내는 답은 봇과의 DM으로 보낸다.
- 답은 아무도 멘션하지 않고, 링크 미리보기를 붙이지 않는다.
- 긴 답은 줄바꿈에서 나눠 여러 메시지로 보낸다.
- 허락을 묻는 카드는 메시지 컴포넌트의 버튼으로 보내고, 정해지면 메시지를 고쳐 버튼을 걷는다.
- 버튼을 누른 것은 Gateway의 `INTERACTION_CREATE`로 받고, 다른 인텐트를 더 켜지 않는다.
- 누를 때마다 바로 상호작용 응답으로 답하고, 주인이 아닌 사람에게는 그 사람에게만 보이는 응답으로 알린다.
- 연결이 끊기면 Discord가 준 주소로 세션을 이어받아 놓친 메시지를 받는다.
- 이어받을 수 없으면 새로 연결한다.
- 하트비트 응답이 오지 않으면 연결을 다시 맺는다.
- 보내기가 제한되면 Discord가 말한 만큼 기다렸다가 다시 보낸다.
- 토큰이 통하지 않거나 Message Content Intent가 꺼져 있을 때만 채널을 끝내고 이유를 알린다.
- 설정창의 Discord 카드에서 켜고 끈다.
- 봇을 만들고 초대하는 안내, 주인의 사용자 id, 토큰을 넣는 가려진 칸을 보여 주고, 토큰이 환경 변수에서 오는지 vault에 있는지 알려 준다.
- `[discord]`는 모델, Slack, Telegram, 기억 검색처럼 모든 PC가 같게 나눈다.
