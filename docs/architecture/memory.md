# 메모리

비서가 몇 달에서 몇 년 동안 기억을 유지하는 방법을 정한다.

## 배경

비서는 최대한 모든 것을 기억해야 한다. 텍스트를 쌓기만 하면 오래 쓸수록 틀린 기억과 오래된 기억이 섞인다. 원본을 남기고 잘 찾는 방식이 사실만 뽑아 정리하는 방식보다 많이 기억한다.

## 내용

- 원본 기록은 SQLite에 두고 고치지 않는다. core의 대화 저장소 역할도 한다.
- 원본 기록은 시간, 채널, 장소, 말한 사람, 역할을 함께 둔다.
- 원본 기록은 항목마다 전체 형식과 함께, 검색에 쓸 시간, 채널, 장소, 말한 사람, 역할, 글을 따로 열로 둔다.
- 원본 기록 표는 트리거로 수정과 삭제를 막는다. 사용자가 지우기를 요청할 때만 그 작업이 트리거를 거친다.
- SQLite 이전의 JSONL 기록은 SQLite 기록이 비어 있을 때 한 번 옮기고 파일 이름을 바꿔 둔다. 비어 있지 않으면 건드리지 않는다.
- 원본 기록 파일은 형식 버전을 갖고, 더 새 버전의 파일은 열지 않는다.
- 대상(사람, 장소, 일), 별칭, 관계 사실, 언급은 [그래프 DB](graph.md)에 둔다.
- 관계 사실은 유효 기간, 대체한 사실, 근거 기록, 출처를 갖는다.
- 바뀐 사실은 덮어쓰지 않고, 이전 사실의 유효 기간을 끝낸 뒤 새 사실과 연결한다.
- 그래프와 검색 색인은 원본에서 다시 만들 수 있다.
- 원본 기록은 즉시 저장하고, 그래프는 백그라운드 작업이 채운다.
- 재시작하면 원본 기록에서 메인 대화를 이어간다. 결과 없이 끊긴 도구와 하위 작업은 중단됐다는 결과를 기록한다.
- 저장소가 실패하면 core는 기록을 버리지 않고 같은 순서로 다시 저장한다.
- 사용자가 기억해 달라고 하면 바로 저장한다.
- 웹페이지와 도구 결과는 기억을 직접 쓰지 못한다.
- 본인에게서 나온 핵심 사실 일부를 프로필로 만들어 항상 시스템 프롬프트에 넣는다.
- 다른 사람에게서 나온 사실은 프로필에 자동으로 올리지 않는다.
- 나머지 기억은 검색 도구로 꺼내고, 결과에 원본 기록 링크를 붙인다.
- 주기적인 정리 작업이 중복을 합치고 바뀐 사실을 대체한다. 한 번에 많이 잃는 정리는 반영하지 않는다.
- 지우기는 사용자가 요청할 때만 하고, 거기서 나온 파생 데이터도 함께 지운다.
- 키워드 검색은 형태소 분석으로 조사와 어미를 떼고 색인한다. 언어를 추가하면 사전만 추가한다.
- 임베딩 모델은 제품 언어 설정마다 하나를 쓴다. 로컬 모델은 100MB 이하다.
- 사용자는 로컬 모델 대신 API 임베딩을 고를 수 있다.
- 벡터마다 만든 모델을 기록하고, 설정이 바뀌면 백그라운드에서 다시 만든다.
- 모델과 검색 방식은 실제 사용에서 모은 평가 세트로 정한다.

## 미정

- 원본 기록 범위: 비서에게 온 메시지만 저장할지
- 기억 보기와 수정 화면
- 정리 작업의 주기와 사용할 모델
