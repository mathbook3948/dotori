# 메모리

비서가 몇 달에서 몇 년 동안 기억을 유지하는 방법을 정한다.

## 배경

비서는 최대한 모든 것을 기억해야 한다. 텍스트를 쌓기만 하면 오래 쓸수록 틀린 기억과 오래된 기억이 섞인다. 원본을 남기고 잘 찾는 방식이 사실만 뽑아 정리하는 방식보다 많이 기억한다.

## 내용

- 원본 기록은 SQLite에 두고 고치지 않는다.
- core의 대화 저장소 역할도 한다.
- 원본 기록은 시간, 채널, 장소, 말한 사람, 역할을 함께 둔다.
- 원본 기록은 항목마다 전체 형식과 함께, 검색에 쓸 시간, 채널, 장소, 말한 사람, 역할, 글을 따로 열로 둔다.
- 원본 기록 표는 트리거로 수정과 삭제를 막는다.
- 지운 기록 표에 번호가 오른 기록만 트리거를 거쳐 지워진다.
- 지운 기록 표는 고치거나 줄일 수 없다.
- 연도별로 나누기 전의 기록 파일은 연도별 기록이 비어 있을 때 한 번 옮기고 파일 이름을 바꿔 둔다.
- 비어 있지 않으면 건드리지 않는다.
- 한 파일 SQLite 기록이 JSONL 기록보다 먼저다.
- 원본 기록 파일은 형식 버전을 갖고, 더 새 버전의 파일은 열지 않는다.
- 원본 기록은 연도별 파일로 나눈다.
- 기록은 그 시간이 속한 연도의 파일에 들어간다.
- 한 번에 저장하는 묶음은 첫 기록의 연도 파일에 통째로 들어간다.
- 새해를 걸친 묶음도 나누지 않는다.
- 기록마다 UUID v7 번호와 만든 PC를 둔다.
- 기록에 남는 PC 번호는 처음 실행할 때 한 번 정하고 바꾸지 않는다.
- 사람이 읽는 PC 이름은 설정창에서 바꿀 수 있고 기록에는 영향이 없다.
- 키워드 색인과 벡터는 기록에서 필요한 열을 옮겨 둔 색인 파일 안의 표를 쓴다.
- 색인 형식이 바뀌면 처음부터 다시 만든다.
- 지난 연도의 파일에는 새 대화를 쓰지 않는다.
- 늦게 도착한 복제 기록과 지우기만 받는다.
- 대상(사람, 장소, 일), 별칭, 관계 사실, 언급은 [그래프 DB](graph.md)에 둔다.
- 관계 사실은 유효 기간, 대체한 사실, 근거 기록, 출처를 갖는다.
- 바뀐 사실은 덮어쓰지 않고, 이전 사실의 유효 기간을 끝낸 뒤 새 사실과 연결한다.
- 그래프와 검색 색인은 원본에서 다시 만들 수 있다.
- 원본 기록은 즉시 저장하고, 그래프는 백그라운드 작업이 채운다.
- 재시작하면 원본 기록에서 각 세션을 이어간다.
- 결과 없이 끊긴 도구와 서브 세션은 중단됐다는 결과를 기록한다.
- 저장소가 실패하면 core는 기록을 버리지 않고 같은 순서로 다시 저장한다.
- 사용자가 기억해 달라고 하면 바로 저장한다.
- 웹페이지와 도구 결과는 기억을 직접 쓰지 못한다.
- 본인에게서 나온 핵심 사실 일부를 프로필로 만들어 항상 시스템 프롬프트에 넣는다.
- 다른 사람에게서 나온 사실은 프로필에 자동으로 올리지 않는다.
- 그래프 DB가 생기기 전의 프로필은 주인이 기억해 달라고 한 메모다.
- 메모는 따로 두고, 메인 세션의 모든 요청에서 시스템 프롬프트 뒤에 붙인다.
- 기억 도구는 `add_memory`, `search_memory`, `erase_memory`다.
- 그래프 DB가 생기면 `add_memory`가 그래프 DB에 넣는다.
- 그래프 DB가 생기면 메모를 모든 요청에 붙이지 않는다.
- 그때는 메시지마다 관련된 기억을 벡터로 찾아 그 메시지에 붙인다.
- `erase_memory`는 메모와 기록을 함께 지운다.
- 메모를 지울 때도 기록처럼 채팅창 카드로 주인의 허락을 받는다.
- 메모는 메인 세션만 바꾼다.
- `add_memory`는 마지막 입력이 주인의 말이고 그 뒤로 다른 도구나 서브 세션 결과가 없을 때만 메모를 바꾼다.
- 루틴과 연동한 사이트를 읽는 도구의 결과는 아무것도 바꾸지 않아서 그 사이에 있어도 된다.
- 서브 세션과 MCP 서버에는 메모 도구가 없다.
- 메모는 주인의 말로 표시해서 붙이고, 줄바꿈과 제어 문자는 공백으로 바꾼다.
- 메모가 주인의 말에서 왔는지는 바꾸는 때로 확인한다.
- `erase_memory`는 입력이 어디서 왔든 메모를 지울 수 있지만, 채팅창 카드로 주인이 허락한 것만 지운다.
- 허락한 일의 결과나 루틴 같은 다른 입력 뒤에는 `add_memory`로 바꾸지 못한다.
- 말투 같은 주인의 규칙도 메모로 둔다.
- 메모는 사실과 규칙을 가리지 않고 모든 요청에 붙는다.
- 메모는 채팅으로 부탁해서만 더한다.
- 설정창의 메모 카드에서는 보고 지우기만 한다.
- 설정창에서 지운 것도 다음 요청부터 모델이 보지 않고 다른 PC에도 간다.
- 원본 기록에는 비서에게 온 주인의 말과 비서가 한 일, 도구와 서브 세션의 결과만 남는다.
- 다른 사람의 말은 주인이 시켜서 읽은 도구 결과 안에서만 남는다.
- 나머지 기억은 검색 도구로 꺼내고, 결과에 원본 기록 링크를 붙인다.
- 주기적인 정리 작업이 중복을 합치고 바뀐 사실을 대체한다.
- 한 번에 많이 잃는 정리는 반영하지 않는다.
- 지우기는 사용자가 요청할 때만 하고, 거기서 나온 파생 데이터도 함께 지운다.
- 메인 세션은 기억 검색으로 찾은 기록 번호로 지우기를 청한다.
- 채팅창 카드가 그 기록과 함께 지울 기록의 내용을 보여 주고, 주인이 허락할 때만 지운다.
- 지울 기록의 번호를 담은 도구 결과와 서브 세션 결과도 함께 지운다.
- 검색 결과가 여기에 든다.
- 비서가 내용을 옮겨 말한 답은 번호가 없어서, 메인 세션이 따로 찾아 함께 지우기를 청한다.
- 카드에 보인 기록만 지운다.
- 카드를 띄운 뒤에 생긴 기록은 다음 지우기로 넘긴다.
- 다른 PC의 지우기를 받은 PC는 그 번호를 담은 도구 결과와 서브 세션 결과도 함께 지운다.
- 지운 기록은 번호와 만든 PC만 남긴다.
- 늦게 도착한 복사본은 받지 않는다.
- 이 PC에 있었거나 도착해서 거절한 기록만 받은 위치에 셈해서, 아직 못 받은 기록을 건너뛰지 않는다.
- 다른 PC가 지운 기록의 만든 PC를 다르게 적으면 그 지우기는 받지 않는다.
- 지운 기록의 키워드 색인과 벡터는 바로 지우고, 지운 자리는 덮어쓴다.
- 다른 PC에서 오는 그 기록의 벡터도 받지 않는다.
- 지운 기록은 실행 중인 메인 세션의 대화에서도 다시 시작하지 않고 바로 빠진다.
- 채팅창에 보이던 카드와 말은 dotori가 다시 시작하면 사라진다.
- 키워드 검색은 형태소 분석으로 조사와 어미를 떼고 색인한다.
- 언어를 추가하면 사전만 추가한다.
- 형태소 분석은 lindera와 mecab-ko-dic 사전을 쓴다.
- 사전은 바이너리에 넣지 않고 처음 쓸 때 받아 해시를 확인한다.
- 사전을 받기 전에는 조사만 떼는 단순 규칙으로 색인하고, 사전이 생기면 색인을 다시 만든다.
- 키워드 색인은 원본 기록과 다른 파일에 두고, 검색할 때마다 원본의 새 기록을 따라 넣는다.
- 기억 검색은 MCP 서버의 도구이고, 서브 세션의 코딩 에이전트도 쓴다.
- 결과마다 원본 기록 번호를 붙인다.
- 기억 검색은 모든 기록을 찾는다.
- 임베딩 모델은 제품 언어 설정마다 하나를 쓴다.
- 로컬 모델은 100MB 이하다.
- 사용자는 로컬 모델 대신 API 임베딩을 고를 수 있다.
- 벡터마다 만든 모델을 기록하고, 설정이 바뀌면 백그라운드에서 다시 만든다.
- 로컬 임베딩 모델은 평가 세트로 고른 뒤 넣는다.
- 그 전에는 API 임베딩을 설정했을 때만 뜻으로 찾는다.
- API 임베딩은 OpenAI `/embeddings` 형식을 쓴다.
- 설정하면 원본 기록의 글이 그 API로 나간다.
- 벡터는 검색 색인 파일에 두고, 백그라운드 작업이 원본의 새 기록을 따라 만든다.
- 검색은 키워드 순위와 벡터 순위를 순위 역수 합(RRF)으로 합친다.
- 임베딩 API가 실패하면 키워드로만 찾고, 결과에 그렇다고 적는다.
- 벡터는 메모리에 올려 전부 비교한다.
- 뜻 검색은 가장 가까운 기록을 늘 내놓는다.
- 맞는 단어가 없어도 결과가 나온다.
- 임베딩 API가 거절한 묶음은 글마다 다시 보내고, 그래도 거절된 글은 벡터 없이 넘어간다.
- 지금 모델의 벡터가 하나도 없으면 질문을 임베딩 API로 보내지 않는다.
- 모델이 바뀌면 이전 모델의 벡터를 지운다.
- 모델과 검색 방식은 실제 사용에서 모은 평가 세트로 정한다.
- 평가 세트는 주인이 질문과, 그 질문으로 찾아야 할 기록에만 있는 글귀를 적은 파일이다.
- 평가는 키워드, 뜻, 둘을 합친 검색을 따로 채점하고, 맞는 기록이 없는 질문은 뺀다.
