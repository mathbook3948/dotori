# LLM 연결

메인 세션이 LLM API와 주고받는 방식을 정한다.

## 배경

core는 대화를 항목 목록으로만 갖고, 공급자마다 형식이 다르다. 연결기가 매번 목록을 공급자 형식으로 다시 만들고, 응답을 행동으로 바꾼다.

## 내용

- 시스템 프롬프트와 모델에게 주는 안내는 영어로 쓴다.
- 시스템 프롬프트에는 비서의 이름, 메시지 태그를 읽는 법, 주인의 메시지만 부탁이라는 규칙, 답하는 법, 말투만 둔다.
- 주인이 쓴 언어로 답하고, 알 수 없으면 설정의 언어로 쓴다.
- 시스템 프롬프트는 언어를 이름 하나로만 알려 주고, 언어마다 규칙을 따로 적지 않는다.
- 말투는 그 언어의 정중하면서 친근한 말투이고, 느낌표와 잘못이 없을 때의 사과를 쓰지 않는다.
- 모델은 `say` 도구로만 말한다.
- 도구 밖의 글은 아무에게도 가지 않는다.
- 서브 세션은 `delegate` 도구로 맡긴다.
- 서브 세션의 모델에는 `delegate` 도구를 주지 않는다.
- 도구 상자에 같은 이름이 있으면 내장 도구가 이긴다.
- 연결기는 요청마다 대화 전체를 공급자 형식으로 다시 만든다.
- 응답은 모델이 읽은 항목 바로 뒤에 놓는다.
- 생각하는 동안 도착한 메시지는 응답 뒤로 간다.
- 응답 원문을 기록에 남기고, 같은 공급자에게는 그대로 돌려보낸다.
- thinking 블록과 도구 id가 유지된다.
- 다른 공급자의 응답은 도구 호출로 다시 써서 보낸다.
- `say`와 `delegate`의 도구 결과는 연결기가 만든다.
- 전달 실패와 서브 세션 결과는 나중에 따로 온다.
- 입력이 잘못된 `say`와 `delegate`는 core에 넘기지 않고 실패 결과로 모델에 알린다.
- 메시지와 알림은 XML 태그로 감싸고 본문의 `<`, `>`, `&`, `"`를 이스케이프한다.
- 메시지 태그에는 주인이 말한 시각을 UTC 차이와 함께 적는다.
- 시간대는 루틴이 읽는 시간대를 따른다.
- 주인이 시간대를 정하지 않았으면 이 PC의 시간대로 적는다.
- 시각은 런타임이 메시지를 받을 때 찍는다.
- 다른 PC에서 넘어온 말은 그 PC에서 말한 때를 쓴다.
- 기록에서 이어 간 대화의 메시지는 그 기록의 시각을 쓴다.
- 시스템 프롬프트에는 현재 시각을 넣지 않는다.
- 시스템 프롬프트는 태그의 `time`이 무엇인지만 알려 준다.
- 응답은 스트리밍하지 않는다.
- 과부하, 속도 제한, 서버 오류는 짧게 몇 번 다시 시도한다.
- 그 밖의 오류는 바로 실패로 돌려준다.
- 거절, 토큰 한도에서 잘린 응답은 실패로 돌려준다.
- Anthropic은 adaptive thinking을 쓰고, thinking 블록 검증이 틀리면 블록만 버리게 한다.
- Anthropic은 거절된 요청을 서버에서 권장 대체 모델로 다시 돌리게 한다.
- OpenAI 호환 API는 chat completions 형식을 쓴다.
- 대화가 길면 요청에는 뒷부분만 싣는다.
- 대화가 약 30만 자(글자 수)를 넘으면 앞에서부터 10만 자 단위로 잘라 내고, 잘린 자리 뒤의 첫 메시지부터 보낸다.
- 그 뒤에 메시지가 없으면 마지막 메시지부터 보내서, 가장 새 말은 길어도 빠지지 않는다.
- 자르는 자리는 10만 자가 더 쌓일 때만 움직여서, 그 사이의 요청은 앞부분이 같다.
- 첫 턴에는 앞부분이 빠졌으니 기억에서 찾으라는 안내를 넣는다.
- 요약 기록이 있으면 요청에 그 요약을 먼저 싣고, 요약이 가리키는 메시지부터 보낸다.
- 요약이 가리키는 메시지가 없으면 요약을 싣고 대화 전체에 같은 자르기를 쓴다.
- 요약 뒤의 대화도 길면 그 메시지부터 같은 자르기를 쓰고, 요약 뒤도 잘렸다는 안내를 넣는다.
- 요약은 지난 맥락이고 새 요청이 아니며, 요약과 최근 메시지가 다르면 최근 메시지가 이긴다고 알려 준다.
- 원본 기록은 그대로 둔다.
- 요약은 메인 모델에 도구 없이 따로 요청한다.
- 요청에는 이전 요약과 그 뒤의 대화를 글로 풀어 싣고, 모델의 생각은 싣지 않는다.
- 도구의 입력과 결과, 맡긴 일의 내용과 결과는 2천 자까지만 싣는다.
- 출력 한도는 답과 같은 값을 쓰고, 길이는 지시문으로 8천 자 안쪽을 요청한다.
- 거절, 출력 한도에서 잘린 답, 빈 답은 실패로 본다.
- 요약이 가리키는 메시지부터의 대화가 25만 자를 넘으면, 모델이 답을 마친 뒤 요약을 만든다.
- 요약은 뒤에서 만들고, 그동안 대화는 평소대로 이어 간다.
- 뒤쪽 10만 자 안쪽은 그대로 두고, 그 첫 메시지를 새 요약이 가리킨다.
- 한 번에 요약하는 대화는 30만 자까지이고, 그보다 오래된 부분은 건너뛴다.
- 요약에 실패하면 아무것도 기록하지 않고, 10만 자가 더 쌓인 뒤 다시 한다.
- 요약을 만드는 동안 기록이 지워지면 그 요약은 버린다.
- Anthropic에는 프롬프트 캐시 표시를 세 곳에 둔다.
- 시스템 프롬프트, 마지막 사용자 턴의 끝, 그 앞 사용자 턴의 끝이다.
- 다음 요청은 앞 요청이 남긴 캐시를 읽는다.
- 시스템 프롬프트에 붙는 주인의 메모는 메모가 바뀔 때만 달라진다.
- 루틴과 연동한 사이트의 목록은 요청마다 붙이지 않고, 모델이 도구로 읽는다.
- 대화 기록이 비어 있는 채로 메인 세션이 처음 시작되면 주인에게 보이지 않는 안내를 한 번 넣어 첫 인사를 하게 한다.
- 다른 PC에 합류한 PC는 첫 인사를 하지 않는다.
- 첫 인사는 메시지 두 개로 한다.
- 첫 메시지는 이름을 밝히며 개인 비서라고 인사하고, 궁금하거나 손이 모자랄 때 언제든 부르라고 한다.
- 두 번째 메시지는 주인을 어떻게 부를지 묻는다.
- 주인이 답한 호칭은 기억에 남긴다.
- OpenAI 호환 API는 따로 표시하지 않는다.
- 모델을 확인할 때는 공급자의 모델 목록을 한 번 부른다.
- 확인은 키가 거절되거나 주소가 답하지 않을 때만 실패한다.
