# 그래프 DB

메모리의 대상과 관계를 저장하고 질의하는 그래프 DB를 Rust로 직접 만든다.

- 상태: 초안

## 배경

메모리는 사람, 장소, 일과 그 관계를 오래 쌓고 빠르게 찾아야 한다. 기존 엔진은 조건에 맞지 않았다.

- Neo4j는 별도 서버다.
- Kuzu는 2025년 10월에 개발이 끝났다.
- Kuzu를 이어받은 LadybugDB는 1.0 전이고 빠르게 바뀐다.

Rust 코드에서 바로 쓰고, 성능을 직접 다룰 수 있게 새로 만든다.

## 내용

- 별도 crate `crates/graph`에 둔다. 메모리를 모르고, core에 의존하지 않는다.
- 내장형이다. 별도 서버 없이 프로그램 안에서 돈다.
- 스키마 없는 속성 그래프다. 라벨과 속성을 미리 정의하지 않는다.
- 질의 언어는 GQL(ISO/IEC 39075)을 기준으로 한다.

### 층

| 층 | 역할 |
|---|---|
| 질의 | GQL 파서, 실행 계획, 실행기 |
| 그래프 배치 | 노드, 엣지, 색인을 키와 값으로 배치 |
| 저장 trait | 읽기, 쓰기, 범위 조회, 트랜잭션 |
| redb 5 | 디스크 저장, 트랜잭션, 복구 |

- 값은 우리가 정한 형식으로 바이트로 바꿔 저장하고, 형식에 버전을 붙인다. redb가 타입 저장 방식을 바꿔도 영향을 받지 않는다.
- 저장 층은 trait 뒤에 둔다. 성능 때문에 바꿀 때 이 구현만 교체한다.
- 버전은 고정하고, 올릴 때 장애 테스트를 다시 돌린다.

### 검증

- GQL과 Cypher가 겹치는 부분은 openCypher TCK로 검증한다.
- GQL에만 있는 부분은 공개 문법을 기준으로 테스트를 직접 쓴다.
- 같은 질의를 LadybugDB에도 실행해 결과를 비교한다.
- 쓰는 도중에 프로세스를 강제로 죽이고, 다시 열어 일관성을 확인한다.
- 파서는 퍼징한다.
