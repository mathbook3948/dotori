# 비밀값 보관

API 키, 봇 토큰, 연동한 사이트의 계정 같은 비밀값을 어디에 두고 어떻게 다른 PC로 옮기는지 정한다.

## 배경

키를 환경 변수로만 받으면 주인이 PC마다 셸 설정을 고쳐야 하고, 창에서 키를 넣을 수 없다. 키와 계정은 설정 파일처럼 평문으로 두면 안 되고, 모델에게 보여서도 안 된다.

## 내용

- 비밀값은 dotori 폴더의 `vault.sqlite3`에 이름별로 하나씩 둔다.
- 키의 이름은 설정에 적힌 환경 변수 이름(`ANTHROPIC_API_KEY` 등)과 같다.
- 연동한 사이트의 계정은 `site:<출처>#<임의의 꼬리표>`라는 이름으로 계정마다 하나 둔다.
- 이름에는 아이디에서 나온 것을 넣지 않는다.
- 같은 출처와 같은 아이디의 계정은 하나만 남긴다.
- 동기화로 같은 계정의 사본이 여럿 생기면 나중에 둔 것을 쓴다.
- `site:` 이름의 값은 키나 토큰으로 읽지 않고, 설정창에서 그 이름으로 키를 넣지 못한다.
- 계정은 키와 같은 이름 수 한도를 나눠 쓴다.
- 값마다 XChaCha20-Poly1305로 따로 잠그고, 이름을 함께 묶어 다른 이름 아래로 옮긴 값은 열리지 않게 한다.
- 여는 키는 32바이트 하나이고 OS 키체인(macOS Keychain, Windows 자격 증명 관리자, Linux Secret Service)에 둔다.
- 키체인을 쓸 수 없는 PC에서는 같은 폴더의 `vault.key`에 주인만 읽을 수 있게 둔다.
- vault에는 그 키로 잠근 확인값을 두고, 확인값을 열지 못하는 키는 쓰지 않는다.
- 키는 값이 처음 들어올 때 `vault.lock`을 잡고 만들고, 값이 없으면 키체인을 건드리지 않는다.
- 키체인 항목은 vault마다 정한 임의의 id로 찾고, 키를 키체인과 파일 중 어디에 뒀는지 vault에 적어 둔다.
- 키체인이 키가 없다고 답했거나, 파일에 둔 키 파일이 없을 때만 키를 잃은 것으로 본다.
- 키체인을 읽지 못하면 새 키를 만들지 않고 실패로 알린다.
- 키를 잃은 PC에서 주인이 설정창에서 키를 다시 넣을 때만 새 키를 만들고, 열 수 없게 된 값은 이 PC에서만 비워 다른 PC의 사본으로 다시 채운다.
- 다른 PC가 보낸 vault는 키를 잃은 vault를 비우지 않는다.
- 같은 이름의 환경 변수가 있으면 그 값을 먼저 쓴다.
- 설정창은 키를 가려진 칸으로 받고, 저장하면 vault에 넣고 칸을 비운다.
- 설정창은 값을 다시 보여 주지 않고, 환경 변수에서 오는지, vault에 있는지, 아직 없는지만 보여 준다.
- vault에 있는 값은 설정창에서 지울 수 있다.
- 창에서는 vault를 "금고"라고 부르고, 값이 안전하게 보관돼 있다는 것과 dotori가 그 값을 대화하는 AI에게 보내지 않는다는 것을 함께 알린다.
- 설정창의 금고 카드는 키와 토큰, 연동된 사이트를 나눠 보여 준다.
- 연동된 사이트는 계정마다 한 줄로 사이트 이름, 아이디, "연동됨"을 보여 준다.
- 설정창에서는 계정을 하나씩 끊을 수만 있다.
- 계정을 끊으면 같은 출처와 같은 아이디의 사본도 모두 지운다.
- 설정창은 계정의 아이디를 보여 주고, 비밀번호와 키의 값은 보여 주지 않는다.
- 사이트를 더하는 일은 채팅창의 카드로만 한다.
- OpenAI 호환 모델에 키 이름이 없을 때 창에서 키를 넣으면 dotori만 쓰는 `DOTORI_MODEL_API_KEY`라는 이름으로 둔다.
- 설정창에서 `DOTORI_MODEL_API_KEY`를 지우면 설정의 키 이름도 지워서 모델이 키 없이 연결한다.
- 제공자를 바꾸면 입력하던 키 칸을 비운다.
- 저장하면 키를 먼저 vault에 넣고, 성공했을 때만 설정 파일을 쓴다.
- vault는 묶인 PC끼리 암호화된 PC 연결로 주고받는다.
- 이름마다 마지막으로 바뀐 쪽이 이기고, 지운 것도 지운 시각과 함께 보낸다.
- 이 PC 시계보다 하루 넘게 앞선 값은 그 값만 받지 않는다.
- 보낼지는 시각이 아니라 이 PC에서 바뀐 횟수로 정한다.
- 키체인을 기다릴 수 있는 일은 PC 메시지를 받는 흐름 밖에서 한다.
- 받은 PC는 자기 키로 다시 잠근다.
- 받은 키는 다른 설정처럼 dotori를 다시 시작하면 쓰인다.
- 모델 키를 기다리는 데몬은 받은 키로 다시 시작하지 않고 바로 시작한다.
- 계정은 브라우저가 로그인 칸을 채울 때마다 금고에서 읽는다.
- 다른 PC에서 받거나 끊은 계정은 다시 시작하지 않아도 바로 쓰인다.
- 키는 모델 설정과 채널 설정을 만들 때만 읽는다.
- 비밀값은 모델의 프롬프트나 도구 결과에 넣지 않는다.
- 메인 세션은 연동한 사이트의 이름, 출처, 계정의 아이디를 `read_sites` 도구로 읽는다.
- 계정의 비밀번호는 모델에게 보이지 않는다.
- MCP 서버는 계정을 넣고 꺼낼 때 금고를 직접 연다.
- 파일 도구는 dotori 폴더를 읽지 않는다.
- dotori의 모델이 실행하는 셸 명령은 [샌드박스](sandbox.md)에서 돌아 `vault.sqlite3`와 `vault.key`를 보지 못한다.
- 셸 명령, 실행 명령으로 띄운 MCP 서버, dotori의 브라우저는 비밀값의 이름으로 된 환경 변수를 물려받지 않는다.
- `PATH`, `HOME`처럼 시스템이 쓰는 이름은 토큰의 이름으로 받지 않고, 명령에서 빼지도 않는다.

## 미정

- 코딩 에이전트 서브 세션과 샌드박스가 없는 PC의 셸 명령은 주인 계정으로 돌아서 `vault.key`를 쓰는 PC에서는 vault를 열 수 있다. Linux Secret Service는 같은 계정의 프로세스를 가리지 않는다.
