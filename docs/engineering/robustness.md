# 견고함

외부 입력, 파일, 자식 프로세스, 실패를 다루는 코드가 처음부터 지킬 것을 정한다.

## 배경

기능 PR마다 리뷰가 같은 종류의 버그를 다시 찾아 고쳤다. 기계로 검사하기 어려운 것들이라 구현할 때 이 목록으로 먼저 점검한다.

## 내용

- 네트워크, 창, 자식 프로세스에서 읽는 줄과 본문에는 길이 한도를 둔다.
- 상대가 보내야 끝나는 읽기와 연결에는 시간 한도를 두고, 받는 연결 수에도 한도를 둔다.
- 사용자나 모델이 준 숫자는 한도로 자르고 포화 연산으로 계산한다.
- 파일 전체를 다시 쓸 때는 임시 파일에 쓰고 rename한다.
- 앱에서는 `replace`를 쓴다.
- 이어 쓰는 기록은 크래시로 잘린 꼬리가 있어도 읽힌다.
- 바이트로 읽고, 한 번에 쓴 묶음이 통째로 남거나 통째로 빠진다.
- 같은 파일이나 폴더를 다른 프로세스가 동시에 쓸 수 있다고 본다.
- 잠금으로 막거나, 남이 만든 결과를 덮어쓰지 않는다.
- 저장 형식에는 버전을 남긴다.
- 띄운 자식 프로세스는 죽으면 다시 띄우거나 실패로 알린다.
- 출력은 끝까지 읽어 막히지 않게 하고, 끝낼 때는 프로세스 트리 전체를 끝낸다.
- 실패한 호출 뒤에는 연결이나 핸들을 다시 연다.
- 다음 입력이 올 때까지 재시도를 미루지 않는다.
- 다시 해도 실패할 것은 재시도하지 않는다.
- 시간 초과와 불러오기에 실패한 자원이 그렇다.
- 패닉한 작업도 결과 이벤트를 남긴다.
- 결과를 기다리는 상태가 영원히 남지 않는다.
- 종료할 때는 남은 답장을 먼저 보내고 채널과 작업을 닫는다.
- Windows에서 다르게 동작하는 것을 확인한다.
- 이어 쓰기 핸들에는 `set_len`을 못 쓰고, npm으로 깔린 명령은 `.cmd` shim이다.
