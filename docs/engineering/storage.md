# 저장

SQLite 파일의 테이블과 열을 어떻게 짓고 관리하는지 정한다.

## 배경

원본 기록, 검색 색인, 메모, 루틴이 각자 SQLite 파일을 둔다. 파일마다 따로 정하다 보니 버전을 남기는 방법과 열 이름이 갈라졌다. 한 규칙으로 맞추고, 기계로 볼 수 있는 것은 `mise run check`가 검사한다.

## 내용

- 테이블과 열 이름은 영어 소문자 snake_case다.
- 시각은 Unix 밀리초 INTEGER로 두고, 열 이름은 `_ms`로 끝낸다. `_at`, `_time`, `timestamp`, `created`, `updated` 같은 이름은 쓰지 않는다.
- 원본 기록은 UUID v7 문자열 `id`로 가리킨다. 원본 기록 파일 밖에서 원본 기록을 가리키는 열은 `record`이고 TEXT다.
- 이 PC 안에서 도착한 순서는 `seq`, 이어 쓰는 목록의 번호는 `n`이고, 둘 다 INTEGER다.
- 같은 뜻의 열은 파일이 달라도 같은 이름을 쓴다. 보낸 사람은 `sender_id`와 `sender_name`으로 나누고 `sender` 하나로 쓰지 않는다.
- 외래 키는 쓰지 않는다. 파일 사이의 참조는 원본 기록 `id`로 한다.
- 테이블 하나는 소스 파일 한 곳에서만 만든다. 다른 모듈이 같은 파일을 쓰면 그 파일을 여는 함수를 함께 쓴다. 파일마다 두는 `meta`만 예외다.
- 파일의 상태 값은 `meta(key TEXT PRIMARY KEY, value)` 테이블에 둔다.
- 파일의 형식 버전은 `PRAGMA user_version`에 두고, 그 파일을 만드는 소스에 `VERSION` 상수로 적는다.
- 원본 기록, 메모, 루틴은 더 새로운 dotori가 쓴 파일을 열지 않고, 버전을 올리기 전에 옮겨 쓰는 단계를 만든다.
- 검색 색인처럼 원본에서 다시 만들 수 있는 파일도 형식이 바뀌면 옮겨 쓴다. 벡터는 다시 만들 때 임베딩 API 비용이 들기 때문이다. 옮길 수 없는 형식만 지우고 다시 만든다.
- 형식을 바꾸는 일은 다른 프로세스를 막는 트랜잭션 하나에서 한다.
- 바뀌면 안 되는 규칙은 트리거로 DB에서 막는다.
