# 테스트

창과 데몬을 어떻게 테스트하고, 에이전트가 화면을 어떻게 확인하는지 정한다.

## 배경

창 코드에는 화면과 떨어진 함수 테스트만 있어서 버튼과 입력이 깨져도 CI가 알지 못했다. 에이전트가 화면을 볼 방법도 세션마다 손으로 다시 만들어야 했다.

## 내용

- 창의 동작은 GPUI 테스트 플랫폼으로 테스트한다. 가짜 채널로 창을 열고 입력과 클릭을 흉내 낸 뒤, 창이 보낸 것과 가진 상태를 확인한다.
- 테스트가 누를 요소에는 `debug_selector`를 붙인다.
- e2e 테스트는 실제 데몬을 띄우고 정해진 대화만 하는 가짜 모델에 붙인다. 창과 같은 방식으로 데몬에 연결해 답, 루틴, 허락과 거절을 확인한다.
- e2e 테스트와 데모는 바깥 인터넷에 나가지 않고, 브라우저나 사전을 내려받지 않고, 실제 API 키를 쓰지 않는다.
- 데모의 데몬은 데모 폴더를 홈으로 써서, 허락한 명령이 사용자의 파일에 닿지 않는다.
- 에이전트는 `.claude/skills/gpui-design/demo.sh`로 같은 가짜 모델과 실제 창을 가상 화면에 띄우고 캡처한다.
- 화면 캡처는 CI에서 비교하지 않는다. 글꼴과 OS마다 픽셀이 달라서다.
