# 테스트

창과 데몬을 어떻게 테스트하고, 에이전트가 화면을 어떻게 확인하는지 정한다.

## 배경

창 코드에는 화면과 떨어진 함수 테스트만 있어서 버튼과 입력이 깨져도 CI가 알지 못했다. 에이전트가 화면을 볼 방법도 세션마다 손으로 다시 만들어야 했다.

## 내용

- 창의 동작은 GPUI 테스트 플랫폼으로 테스트한다.
- 가짜 채널로 창을 열고 입력과 클릭을 흉내 낸 뒤, 창이 보낸 것과 가진 상태를 확인한다.
- 테스트가 누를 요소에는 `debug_selector`를 붙인다.
- 문구를 확인하는 테스트는 시스템 언어를 따르지 않고 한국어와 영어를 정해서 확인한다.
- 조사처럼 모양이 바뀌는 한국어 문구는 몇 곳에서 문자열 그대로 확인한다.
- 영어 문구 표에 한글이 없는지는 문구를 만드는 함수를 모두 불러서 확인한다.
- e2e 테스트는 실제 데몬을 띄우고 정해진 대화만 하는 가짜 모델에 붙인다.
- e2e 테스트는 디버그 빌드에만 있는 테스트용 환경 변수로 트레이 없이 데몬을 띄운다.
- 창과 같은 방식으로 데몬에 연결해 답, 루틴, 허락과 거절을 확인한다.
- 창이 처음 붙으면 지난 대화 끝에 `Live`가 오고, 주인이 말하면 `Working`이 오는 것도 확인한다.
- e2e 테스트와 데모는 바깥 인터넷에 나가지 않고, 브라우저나 사전을 내려받지 않고, 실제 API 키를 쓰지 않는다.
- 데모의 데몬은 데모 폴더를 홈으로 써서, 허락한 명령이 사용자의 파일에 닿지 않는다.
- 에이전트는 `.claude/skills/gpui-design/demo.sh`로 같은 가짜 모델과 실제 창을 가상 화면에 띄우고 캡처한다.
- 데모는 가상 화면에서 `dotori`를 주인이 실행할 때처럼 트레이와 함께 띄운다.
- 데모는 가상 화면의 채팅창에 직접 입력해서 dotori와 대화한다.
- Windows에서는 `.claude/skills/gpui-design/win.ps1`로 보이지 않는 데스크톱에 창을 띄우고, 입력은 창 메시지로 보내고, 창이 그린 그림을 받는다.
- macOS에서는 `.claude/skills/gpui-design/mac.sh`로 창을 모든 화면 밖에 포커스 없이 띄우고, 그 창만 `screencapture`로 찍는다.
- macOS 데모는 트레이 없이 데몬을 띄우고, 주인의 말과 허락은 `demo_owner` 예제가 창처럼 데몬에 연결해서 보낸다.
- 에이전트는 사용자의 마우스, 키보드, 화면을 쓰지 않는다.
- 데모의 가짜 모델은 답하기 전에 1.5초 생각해서, 일하는 동안의 창도 찍을 수 있다.
- 화면 캡처는 CI에서 비교하지 않는다.
